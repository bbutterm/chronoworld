# Chronoworld — памятка для агента (читается в начале каждой сессии)

Мобильная idle-RPG в духе AFK Arena с миром и артом Ragnarok Online. TypeScript + Phaser 3 + Vite, тесты — Vitest.
Детерминированное ядро без Phaser — `src/core`, экраны — `src/game`, весь контент и числа — JSON в `data/`
(проверяется zod-схемами). Прод — Vercel из ветки `main`. Интерфейс и документация — на русском.
Цель — Telegram Mini App (пока веб-сборка).

## Золотые правила

- **Ядро детерминировано.** В `src/core` нет `Date.now()`, `Math.random()`, `new Date()`, Phaser и DOM. Случайность —
  только `Rng` (`src/core/rng.ts`) с seed; время и «день» UI передаёт параметрами (`now`, `day`). Один seed — один лог боя.
- **Контент — только через `data/` и схемы.** Новый юнит/навык/глава — JSON-файл, код не трогаем. Поле добавляется в zod-схему
  (`src/core/content/schema.ts`, `src/core/story/schema.ts`, `src/core/campaign/schema.ts`, `src/core/progression/schema.ts`…),
  затем `npm run content:schema` (перегенерирует `data/schema/*.json`). Заготовки — `npm run content:new`.
- **`npm run check` должен быть зелёным** перед каждым коммитом (content:check + tsc + vitest; то же гоняет CI).
- **Тесты не отключать и не пропускать** (`.skip`, `.only`, ослабление порогов «чтобы прошло» — нельзя). Упал тест —
  чинить код или осознанно обновить ожидание с объяснением в коммите.
- **Весь текст для игрока — на русском** (названия, кнопки, подсказки, ошибки контента). Идентификаторы — латиница `a-z0-9_`.
  Английский — перевод при выводе (`locales/en`, `docs/AGENTS.md` §15): после правки текста `npm run i18n:extract`
  и заполнить пустые переводы, иначе `tests/i18n.test.ts` красный.
- id этапов, профессий, карточек героев (`data/heroes`), предметов и сюжетных сцен после выпуска не переименовывать — они лежат
  в сохранениях игроков. Старые сохранения (v3) читает замороженная миграция `src/core/heroes/migrate.ts` — её не менять.
- Не трогать файлы, которые по плану принадлежат другому агенту (см. «Сабагенты»).

## Git: как работает владелец

- Рабочая ветка графики — `codex/graphics-integration`; `codex/rpg-autobattler` уже слита,
  `claude/idle-hero-rpg-gdd-rolicg` — историческая. Прод — `main` (Vercel собирает каждый пуш в main).
- Готовая работа → PR из рабочей ветки в `main` → слить, когда CI (`.github/workflows/check.yml`: check + build) зелёный →
  после слияния сбросить рабочую ветку на `origin/main` (`git fetch origin && git reset --hard origin/main`, затем push).
- Владелец иногда сам кладёт арт прямо в `main` — перед работой подтянуть: `git fetch origin && git merge origin/main`.
- Сабагенты работают в своих git worktree (`.claude/worktrees/…`) со **строгим владением файлами**: в задании перечислено,
  какие файлы агент может менять. Первая команда сабагента — `git fetch origin && git merge origin/claude/idle-hero-rpg-gdd-rolicg`
  (worktree создаются от старого коммита). Сабагент коммитит в своей ветке и не пушит; оркестратор сливает ветки
  сабагентов в рабочую, решает конфликты и сам гоняет `npm run check` (и e2e, если трогали экраны).
- Атрибуция коммита/PR должна соответствовать действительно использованному инструменту. Не добавлять чужое имя,
  вымышленную ссылку на сессию или несуществующего соавтора.
- Никогда не писать в коммиты, PR и документы идентификаторы моделей (вида `claude-…`) — только имя из трейлера.
- Push — только когда просит владелец или оркестратор; интерактивные git-команды (`-i`) недоступны.

## Общение с владельцем

Владелец пишет из мессенджера, похожего на Telegram: markdown там отображается плохо. Для ответов и особенно для
промтов, которые он будет копировать (художнику, другому агенту), — простой текст: без таблиц, без вложенных списков,
без `**` и `#`; короткие абзацы, нумерация «1.» допустима. Отчёты — кратко: что сделано, что проверено, что нужно от него.

## Команды

| Команда | Зачем | Грабли |
| --- | --- | --- |
| `npm run check` | content:check + typecheck + все vitest-тесты | ~15 с здесь; тест «1000 боёв быстрее 2 секунд» (`tests/sim.test.ts`) меряет CPU и сравнивает с эталоном — при сильной параллельной нагрузке перезапустить отдельно, а не ослаблять |
| `npm test` | только vitest (`tests/**/*.test.ts`) | `npx vitest run tests/x.test.ts` — один файл |
| `npm run content:check` | схемы, ссылки, ассеты, спрайтшиты, дымовой бой каждого юнита и профессии, TODO заготовок | ⚠ — предупреждения (не ошибки), ✗ — ошибки |
| `npm run content:new -- <unit/skill/hero/chapter/stage/story/boss> <id> …` | заготовки контента (`scripts/lib/content-gen.ts`) | не перезаписывает файлы; «TODO» в заготовках content:check покажет предупреждениями |
| `npm run content:schema` | перегенерировать `data/schema/*.json` после правки zod-схем | иначе content:check упадёт «устарел» |
| `npm run playthrough -- [глава] [попыток] [--winrate N] [--idle]` | прохождение главы ядром как новый игрок; доля побед перед этапом | глава — индекс с 0; `--winrate 600` медленно (минуты) — в фон |
| `npm run balance` | модель игрока на 14 дней → `balance.csv` (gitignored) | `-- --days 10 --sessions 6 --out /tmp/b.csv` |
| `npm run sim -- --a <отряд> --b <отряд> --n 1000` | серия боёв юнитов из `data/units` | `--log --seed 7` — лог одного боя |
| `npm run e2e` | дымовой прогон в браузере: Кампания → бой → итоги, вкладки Город и Приключения | сам поднимает vite на `E2E_PORT` (5173) |
| `npm run e2e:chapter1` | глава 1 целиком через интерфейс, проверка перекрытия кнопок | порт 5174 (`E2E_PORT`); несколько минут — в фон |
| `npm run perf` | замер боя в браузере (CPU ×4), утечки между боями | порт 5185 (`PERF_PORT`), `PERF_RUNS`, `PERF_JSON` |
| `npm run assets:report` | какие ассеты попадут в dist, лишние, листы > 2048 px | |
| `npm run assets:webp` | WebP без потерь для всех PNG из dist → `assets-webp/` (коммитить) | после замены/добавления арта; нужен Pillow; устаревшие копии сборка не берёт |
| `npm run perf:load` | холодный старт прод-сборки: CPU ×4, Fast 3G — заставка, экран загрузки, главная | порт 5190 (`LOAD_PORT`), `LOAD_RUNS`, `LOAD_JSON` |
| `npm run build` | tsc + vite build в `dist/` (как Vercel) | в dist копируются только используемые ассеты (`scripts/lib/used-assets.ts`) |
| `python3 -m unittest discover -s tests -p 'test_*.py'` | проверки арт-пайплайна (листы, иконки, тайлы) | нужен Pillow/numpy; в `npm run check` не входят |

Браузерные прогоны (e2e, e2e:chapter1, perf): Playwright установлен глобально (`npm root -g`), Chromium уже лежит в
`/opt/pw-browsers` (`PLAYWRIGHT_BROWSERS_PATH`). **Никогда не запускать `playwright install`** и не ставить playwright в проект.
Параллельные прогоны — на разных портах. В worktree нет `node_modules` — сделать симлинк на `node_modules` основного
checkout (`ln -s /home/user/chronoworld/node_modules node_modules`). Не менять файлы во время e2e: vite перезагрузит страницу
и прогон упадёт. Контейнер медленный — долгие команды запускать в фоне и дожидаться уведомления.

  cardDrops), `data/cards.json` (редкости зелёный → красный, «3 одинаковые = следующая редкость», уровень из общего пула опыта
  `resources.heroExp` + золото), `data/summon.json` (Таверна). Осколков нет — копии того же героя и карты случайных героев.
  Сохранение v7; замороженные миграции `src/core/heroes/migrate.ts` (v3→v4) и `migrate-v7.ts` — не менять. API экранов —
  `docs/AGENTS.md`, раздел 2а. Опыт наград (`rewards.jobExp`) идёт в пул.
- Кампания — маршрут из 10 глав по классическому RO (`docs/design/lore-route.md`, библия `docs/design/story.md`): все 10 глав

  (`theme`), не по месту. Монстры — на листах из клиента RO (`docs/RO_SCRO_IMPORT.md`), заплатки остались у немногих.
  Кнопок тестировщика больше нет: «Настройки → Коды» (`data/codes.json`, `src/core/codes`): `helloworld` — один раз
  +300 алмазов. Многоразовые `300` и `12` доступны только в dev/сборке лаборатории; в проде исключены.
- Мета: экспедиции (`src/core/meta/expeditions.ts`), события/почта (`src/core/events`), открытия по этапам (`data/unlocks.json`),
