# Поставка листов героев из ART_REQUEST_HEROES.md

Готовые файлы — `assets/sprites/heroes/<id>.png`, `assets/sprites/portraits/<id>.png`, регистрация — `assets/sprites/sprites.json` (schema 2). Полный перечень id — в исходном `docs/ART_REQUEST_HEROES.md`: 13 первых профессий/новичок, 16 вторых, 11 сюжетных/NPC = 40 вариантов. В этой поставке добавлены недостающие 23 листа/портрета; ранее добавленные 17 портретов доведены до 256×256. Листы 1792×1152 (8 столбцов, 6 анимаций, клетка 224×192, x1, RGBA/indexed PNG). Портреты 256×256 — **nearest-neighbor увеличение кадра 64×64**, а не новая детальная иллюстрация.

Источники — RO ACT через `https://assets.latam-tools.com.br/image`, `tools/fetch_sprites_v2.py` + `tools/build_sprites_v2.py`; параметры job/gender/head/palette/оружия каждого персонажа и индексы кадров записаны в `sprites.json`. `headPalette` выбиралась по реальному цвету в этом рендерере (номера палитры не совпадают с словесными названиями цвета в заявке). Отдельные анимационные кадры могут скрывать экипировку: ограничение исходного рендерера, не отдельный ручной дорисованный слой оружия. Некоторые позы смерти повторяют последний доступный ACT-кадр.

Все первые профессии (`visual.sprite` профессии + варианты по полу) входят в production-сборку. Сюжетные id `hero_*` и `npc_garret` зарегистрированы, но **пока не используются сценами**; сборка копирует в `dist` только ассеты, на которые ссылается контент. Подключать их в диалоги нужно с учётом выбранной игроком профессии, иначе можно ошибочно показать novice после её смены. Не утверждать, что эти 11 листов уже видны игроку.

Проверки: `python3 tools/check_sprites.py`; отдельная сверка каждого из 23 новых листов с кэшем источника через `--source-cache ... --only <id>`; `npm run check`, `npm run build`, `npm run assets:webp`. Глобальный `--source-cache` для всех 82 листов зависит от исторического кэша монстров/старых героев, который может отсутствовать.
