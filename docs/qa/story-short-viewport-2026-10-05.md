# Истории и окна летописи на коротком экране, 05.10.2026

Пакет исправляет подтверждённые ошибки окон чтения. Он не меняет сюжет, награды, ядро, формат сохранения,
арт или правила открытия личных историй. Новая графика отложена владельцем до загрузки.

## Подтверждённые ошибки

1. В `openHeroStory` кнопка закрытия находилась за безопасной нижней границей Telegram.
   На Canvas360×640 её низ был 1894 при `safeBottom=1410`. На WebGL390×844 —1894 при 1866.
   SDK Back уводил из карточки в список героев и оставлял прежнюю область прокрутки заблокированной.
2. В `loreModal` неподвижная шапка вытесняла текст и кнопки на коротком экране. На 360×640
   дополнительная кнопка занимала 1720…1840, а маска текста доходила до 1698 при `safeBottom=1410`.
3. Страницы `showPages` уже поддерживали короткий экран, но не регистрировались для SDK Back:
   открытый эпизод из летописи уводил в город вместо закрытия страницы.
4. Список истории главы сразу запускал пересмотр до окончания закрытия нижнего листа.
   Фон летописи разблокировался ещё во время пересмотра. На законном сохранении 180 этапов
   SDK Back из пересмотра уводил в город при неизменном сохранении.
5. В компактном `ChapterDone` собственные вызовы страниц и истории не передавали прокрутку тела.
   При реальном колесе внутри страницы offset фона менялся 0→180; внутри открытого списка истории —360→180.
   Его зарегистрированные окна также не имели обработчика SDK Back: сцена не вызывает общий `screen`.
   Последний дефект относится к общему контроллеру и исправляется отдельным владельцем `screen.ts`.
6. При закрытии личной истории `HeroScene` перезапускал карточку с начальным offset.
   Реальные значения 720 и 180 сбрасывались в 0, хотя герой, вкладка и отметки чтения сохранялись.

## Изменения

- `loreView.ts`: шапка, иллюстрация и текст входят в одну прокручиваемую область; кнопки остаются внутри безопасной
  области и имеют цель не меньше 44CSSpx. Resize меняет поверхность и маску без потери положения.
- `heroStoryView.ts`: зарегистрированное окно с доступным нижним действием, обновляемой маской и сохранением offset
  при resize. Закрытие и внешний DESTROY восстанавливают именно захваченную область и её прежний `locked`.
- `storyPage.ts`: зарегистрированный модальный слой, optional `lock`, один callback завершения при обычном закрытии.
  Внешний DESTROY не помечает сюжет завершённым. Пустые страницы возвращают `null` без блокировки.
- Отдельная функция `openStoryHistory` поверх замороженного `ChapterDone` 251960: optional `lock`, возврат слоя,
  запуск пересмотра после `bottomSheet.onClose`. Фон остаётся заблокированным до окончания readOnly replay;
  shutdown и внешний DESTROY отменяют устаревший переход. Два разрешённых вызова передают `bodyArea`.
- Отдельный маленький `HeroScene` delta: callback истории передаёт `bodyOffset` при возвращении. Новое тело
  применяет offset после построения и ограничивает его реальной высотой. Полный `back` сохраняется.

## Приёмка собранной версии

Четыре цепочки собранной игры прошли на Canvas 360×640 и WebGL1 390×844:
Boot → Heroes → Hero → личная история, затем настоящий вход в летопись из города,
запись героя → личная история → эпизод → список увиденных сцен → readOnly replay.
32 физических касания, 4 CDP-жеста, 20 проверок resize, включая открытые окна на 390×844→640→760→844.
Жесты действительно сдвигают текст окна примерно на 160 единиц мира; фон остаётся на месте.
SDK Back закрывает только верхнее окно, вкладка и герой сохраняются, история героя возвращает прежний offset,
readOnly replay оставляет сохранение побайтно точным. Ошибок `pageerror` и загрузок UI-исходников нет.
Видимый текст проверен на размер не меньше 12 CSS px, нижние действия — на цель не меньше 44 CSS px.
