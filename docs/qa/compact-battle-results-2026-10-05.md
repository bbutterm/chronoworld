# Короткий Telegram: бой, результат и завершение главы — 05.10.2026

## Причина и границы исправления

Бой и конечные экраны размещали элементы по постоянной высоте 1920. На телефоне 360 × 640
с Telegram safe area 47/34 CSS px и верхней content safe area 89 CSS px доступная высота
интерфейса составляет 1410 единиц мира. Фиксированное поле, медальоны ульт, награды и нижние
действия не помещались в эту область. Позднее получение Telegram insets также не меняло уже
созданные элементы. Простое уменьшение всей сцены сделало бы подписи и области касания меньше.

Пакет меняет только экранное размещение в Battle, Result и ChapterDone. Арт, сохранения,
боевые правила, положения ядра, RNG, выдача наград и длительность эффектов не меняются.
Для браузерной проверки используется read-only зеркало окончательных `src/core`/`data` из root
и общей адаптивной основы. Эти зеркала не входят в пакет.

## Размещение

- `battleScreenLayout.ts` вычисляет границы поля, HUD, нижних действий, результата и главы
  из `view().uiHeight`/safe area. Кнопки используют минимальную область касания 44 CSS px,
  подписи сохраняют минимальный размер 12 CSS px. Доступные скорости берутся из конфигурации:
  здесь это ×1 и ×2, с циклическим возвратом ×2 → ×1.
- Battle проецирует исходные боевые координаты в доступное поле. Габариты всех зарегистрированных
  анимаций определяют допустимый экранный масштаб; крупный Lord сохраняет native scale 2
  и исправленную зону касания. Панель из пяти медальонов ульт, HUD, подписи и временные реплики
  получают новую геометрию без пересоздания боя. `BarkLayer.reflow` сохраняет активный текст,
  объект и оставшееся время реплики, ограничивая её актуальными краями поля.
- Result всегда создаёт прокручиваемое содержимое, даже если первый размер экрана полный.
  Награды, события, состав отряда и MVP находятся выше закреплённых действий. Изменение insets
  сохраняет существующее содержимое и offset, при необходимости ограничивая его новыми границами.
  Статистика использует адаптивную нижнюю панель с обрезкой прокрутки и доступным крестиком.
- ChapterDone разделяет прокручиваемые цитату, приглашение героя, историю и дополнительные
  действия от закреплённого перехода к кампании. История главы открывается в адаптивной
  прокручиваемой панели. Изменение высоты сохраняет заработанный итог и не запускает его заново.

Обработчик изменения вида меняет только существующие экранные объекты. Он не вызывает
повторную симуляцию, создание сцены, проигрывание журнала с начала или сохранение наград.
Тела павших остаются в последнем показанном месте. Общие Float/Ult presenters не изменяются.

награды и ожидающего завершения главы проходят без изменения требований.

## Реальные действия и динамические insets

`scripts/night-compact-battle-qa.mjs` открывает локальный браузер с законным профилем,
завершает реальные startup overlays и нажимает доступную кнопку Stage. Для изолированной
проверки перед этим нажатием включает `?compact=1` без изменения размера подготовительной
сцены. Бой начинается один раз. Во время боя Telegram content inset меняется 89 → 109 CSS px,
затем safe/content insets убираются и возвращаются. Соответствующая высота интерфейса:
1410 → 1350 → 1920 → 1410.

На каждом изменении одновременно сверяются ссылки result/log/save, seed, cursor/clock,
createSeq, очередь ввода, committed, core positions/offsets, HP/энергия/щит/жизнь, байты
сохранения и количество записей в storage. Они остаются прежними. Часы остановлены только
на время этих сравнений; проверки последующих боевых действий продолжают бой.
Дополнительно реальное окно меняется 360 × 640 → 390 × 844 → 360 × 640 в том же живом
бою. Оба изменения проходят те же сравнения; показанная высота меняется до 1866,46 и обратно
до 1410. Видимые подписи боя сохраняют минимум 12 CSS px (13 CSS px при ширине 390).

| Сценарий | Профиль | Проверки | Ошибки |
|---|---|---:|---:|
| Победа, Canvas 360 × 640 / Telegram | Законный `after-ch10_s18`, 180 очищенных этапов | 30 / 30 | 0 |
| Поражение, Canvas 360 × 640 / Telegram | Законный `before-wall-ch10_s13` | 24 / 24 | 0 |

Победный прогон нажимает реальные ×2 → ×1, переводит ульты в ручной режим, дожидается
заработанной энергии и нажимает готовый медальон. В очередь добавляется ровно одна ульта.
Результат этого ручного боя: winner A, seed `4171357815`, длительность 69,5 с.
Затем проходят Result → прокрутка → статистика → изменение insets → крестик → кампания,
заработанный итог главы 1 (18/18) → прокрутка → история → изменение insets → крестик → кампания.
Нижние действия не перемещаются вместе с содержимым. Видимые подписи в Result, ChapterDone
и панелях статистики/истории имеют минимум 12 CSS px, области действий — минимум 44 CSS px.

Профиль поражения получен честным драйвером кампании. В реальном UI бой имеет seed
`1383411259`, winner B, reason `wipe`, длительность 96,8 с. Характеристики и ресурсы не
подменяются; автоматические ульты остаются включены. Проходят те же изменения insets,
скорости, прокрутка результата, статистика, история заработанной главы и реальные переходы.
Проверка требует именно поражение, поэтому случайная смена результата не считается PASS.

Локальные доказательства:

## Независимая проверка полного Lord replay

Независимый QA использует законный AFTER профиль рационального seed2-драйвера:
`/tmp/chronoworld-night-after-rational-seed2/saves/after-ch10_s18.json` и соседние часы,
180 очищенных этапов, игровой день 22.10.2026. Реальный повтор 10-18 имеет seed `2763811228`,
winner A, длительность 81,8 с на обоих рендерах. Это другой профиль, чем в прежнем отчёте
BUG158: его старые 345 замеров / 67,5 с не переносятся в новую таблицу.

| Независимый compact прогон | Закрыто больше половины героя | Максимум всех raw samples | Клик по видимому боссу | Ошибки / пересечения подписей |
|---|---:|---:|---|---:|
| 390 × 844 Telegram / WebGL1 | 0 / 416 | 0% | B1, имя alpha1 | 0 / 0 |
| 360 × 640 Telegram / Canvas | 0 / 416 | 1,780% | B1, имя alpha1 | 0 / 0 |

Метрика считает общие непрозрачные пиксели текущего кадра босса и живого героя, только если
босс находится выше героя в порядке отрисовки. Учитываются trim, отражение, контейнер,
камера и alpha threshold 32/255; пустая клетка листа не считается телом. Строгая проверка
касания выбирает доступный видимый пиксель босса с учётом higher-depth соседей, проверяет
реальный `hitTest`/порядок ввода и нажимает мышью. Масштаб Lord остаётся 2.

Оба прогона полностью проходят Result → статистику → прокрутку → крестик → кампанию
через реальные действия. Во время живого боя два изменения Telegram inset 156 → 136 CSS px
сохраняют те же scene/result, cursor/clock, core units и save. Дополнительные изменения
viewport в Result и открытой статистике сохраняют существующие данные/сохранение и
проверяют реальный рендер, подписи минимум 12 CSS px и доступные области касания 44 CSS px.

Полный Result/statistics/navigation проверяется на AFTER профиле: первая победа штатно
показывает финальный сюжет Греты и переводит в ChapterDone («Смена караула»). Этот переход
сохранён. Для BEFORE профиля не заявляется проверка статистики, которая в таком потоке
не была открыта.

Независимые доказательства: `/tmp/night-compact-lord-390-webgl-final/report.json` и
`/tmp/night-compact-lord-360-canvas-after/report.json`, `battle-name.png`, `battle-mid.png`,
`result-stats.png` и `result-stats-enemies.png` в соответствующих папках. Рендер каждого
замера реальный; боевые обновления 30 Гц, замеры 0,2 с, `--render-every 6`. Native RAF
возвращается до конечных экранов. Семь product source hashes сверяются с отдельным

после интеграции; локальные dev доказательства её не заменяют.
