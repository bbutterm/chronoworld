# Оптимизация поиска позиции в бою

Нагрузка `tests/sim.test.ts` показала повторные вычисления и аллокации в `findSpot` и `clearance` (~18% выборки CPU). Углы веера теперь вычисляются один раз без хуков, точки — по мере проверки. Когда зазор уже не позволяет кандидату обойти лучший fallback, дальнейшие расстояния не считаются. Другие вызовы `clearance` получают прежний точный минимум. Для хуков сохранено чтение изменяемого `combat` из API при каждом поиске.

Порядок выбора, все формулы и округления сохранены. Тики, RNG, навыки, фазы и энергия не менялись. Патч затрагивает только `src/core/battle.ts`.

В сравнении old/new по 500 боёв лучшая пара CPU: с правилами 1175,804 → 1103,951 мс; без правил 979,864 → 963,897 мс. Отношение 1,2000 → 1,1453. Это сравнение в одном процессе с тремя повторами и чередованием порядка old/new.

Финальный исходный `tests/sim.test.ts` в тихом слоте без браузеров: 4/4 зелёные, 7,56 с; строгий порог 1,25 сохранён. Проверки поведения, боёв, решений, героев — 140 зелёных; lifecycle — 11. `tsc --noEmit` и `git diff --check` зелёные. После объединения полный root `npm run check` прошёл: 2018 Vitest-тестов в 182 файлах и три Node perf helpers, без ослабления исходных ограничений; production build успешен.

240 полных результатов и логов old/new совпали побайтно: 12 seed, пять сценариев (зеркало героев, ранняя кампания, Осирис, поздний босс), оба режима поведения и ручной ульты. Дополнительно 12 боёв с хуками, меняющими сами углы/размер списка и `crowdSquash` внутри боя, также совпали побайтно. Frozen content и общие зависимости совпадают с текущим root (SHA256 в manifest).
