## Проблема и результат

UI обещает близость за главу, пройденную вместе. Раньше `finishEvening` награждал текущий отряд при чтении вечера.
Если сменить его после победы или вернуться к вечеру позже, награда доставалась другим героям.

Теперь первая победа **последнего по контенту этапа главы** сохраняет templateId участников в optional
`save.tavern.chapterSquads[chapterId]`. Снимок сделан по реальным карточкам боя до наград и вербовки:
товарищ, присоединившийся после победы на свободное место, не считается её участником.
Позднее чтение вечера и повторная победа другим отрядом сохраняют эту историю.
Начисление происходит по прежним правилам: при завершении/пропуске вечера, с прежним потолком и только один раз.

Общий чистый helper `eveningSquadHeroes(save, eveningId, ctx)` экспортирован из `src/core`.
Он возвращает участников для расчёта и UI preview. Runtime UI owner должен заменить использование текущего
`storyHeroesInSquad` при объяснении прибавки в `TavernEveningScene`; этот пакет UI не изменяет.

## Совместимость и восстановление

- Отсутствующий снимок старого сохранения сохраняет прежний fallback текущего отряда; прошлые участники
  не придумываются и не создаются при повторном прохождении уже очищенной главы.
- Явный пустой снимок остаётся пустым и не превращается в награду новому отряду.
- Повреждённая отдельная запись превращается в пустую; повреждённый весь metadata map — в пустой map.
  Основные ресурсы, герои, кампания, прочитанные вечера и доверие сохраняются.
- `sanitizeSave` удаляет неизвестные главы/героев, повторы имён и записи для непройденных глав.
  Известная глава с одними удалёнными героями сохраняет пустой снимок. Владеть конкретным старым экземпляром
  для исторического кредита не требуется: данные хранят templateId.
- Уже прочитанный вечер не награждает снова. Выборы и другие операции таверны сохраняют snapshot map.
  Версия v7, облачный protocol, frozen migrators и SQL не менялись.
