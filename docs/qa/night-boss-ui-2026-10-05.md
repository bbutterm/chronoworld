# Ночная приёмка BUG-158 и BUG-117

Проверены существующие спрайты и настоящие `Battle`/`Result` из законных сохранений
ускоренного прохождения. Продукционные сцены, данные и ассеты этим QA не изменялись.

Пункт BUG-158 про перекрытие героев Владыкой мёртвых воспроизведён и прошёл независимую
приёмку исправления. Максимальное закрытие фигуры снизилось со 100% до 0,65–0,68%,
а количество кадров с закрытием больше половины героя — с 297 до нуля. Имена и
полосы подготовки находятся над фигурами и этого дефекта не имеют.

У BUG-117 перекрытие имени Золотого жука сейчас не воспроизводится. Имя показывается
настоящим касанием, целиком присутствует в статистике и не пересекается с портретом.
Существующий `elite.png` заметно отличается от новых RO-героев; замена/доработка арта
отложена до загрузки владельцем. Рекомендуемый статус оставшейся части BUG-117: 🎨.

## Итоги боя и названия

Проверена последовательность `Stage → Battle → Result → Статистика → × → К кампании`.
Накопленные баннеры открытых функций законного CLI-профиля закрываются кнопкой «Позже»;

«Золотой жук-вор» и «Владыка мёртвых» показаны полностью, без эллипсиса. Их портрет
занимает world x `54…138`, имя начинается с x `162`: запас **24 world**, пересечения

На baseline 360×640 с указанными TG-отступами основной контент имеет CSS ширину около 264 px;

а не новое перекрытие имени спрайтом. Этот снимок предшествует отдельному пакету
responsive foundation; его приёмка не подменяется проверкой presentation-исправления.

## Метод измерения

На каждом семпле текущий packed frame восстановлен из source image, cut rectangle,
trim offset, origin, отражения и `sprite.getWorldTransformMatrix()`. Использована та же
поправка зеркального origin, что у Phaser MultiPipeline. Альфа сравнивается при текущем
CSS масштабе `view.cssW / view.worldW`; непрозрачными считаются пиксели alpha ≥32/255.

Для каждого живого видимого героя вычислено пересечение непрозрачных пикселей босса
и героя. Оно считается закрытием только при глубине босса выше героя; одинаковая
глубина разрешается порядком display list. Знаменатель — все непрозрачные пиксели
текущего кадра героя. Пустые прямоугольники больших sprite cells не считаются телом;
оружие текущей анимации считается, поскольку реально скрывает фигуру. Метрика не
оценивает художественное качество и не считает отдельные VFX частью фигуры босса.

Точка касания выбирается из видимых непрозрачных пикселей босса: вычитаются фигуры
с большим render-list rank. Каждый оставшийся кандидат проходит настоящий Phaser
`InputManager.hitTest` и сортировку; верхней интерактивной целью должен быть именно
sprite босса. Это исключает и невидимый пиксель за Банши, и прозрачный край чужого
прямоугольника ввода. Затем выполняется реальный mouse click по camera.matrix,
с учётом shake и плотности canvas; `nameAlpha = 1` остаётся обязательным.
Если доступной точки нет, проверка падает, а не вызывает `flashName` искусственно.

Максимум берётся из **всех семплов**. Обновление representative PNG с порогом 2%
используется только для ограничения числа снимков и не округляет итоговую метрику.

Бой обновляется с 30 Гц, синхронизированы частные `Date.now`, `performance.now` и
`game.loop.time`: одни Game.step без этих часов не воспроизводят Phaser TweenManager
и reveal правильно. Семплы снимаются каждые 0,2 с. При `--render-every 6` промежуточные
шаги обновляют анимацию без рисования; каждый семпл следует реальному WebGL/Canvas render.
`postrender(null)` headlessStep **не учитывается** как успешный render. Default `1`
рисует каждый шаг. Перед созданием `Result` восстановлены родные часы и RAF;
модальные окна, задержки ввода и переход назад проверены обычными кликами.
FPS физического устройства этим прогоном не измеряется.

Неверная сцена, незавершённый бой/Result, недостигнутая статистика, незакрытый лист,
непоказавшееся имя по касанию, потеря source, отсутствие последующих реальных render
или page/console error дают `exit 1`. Незавершённые ранние отладочные прогоны helper
не включены в таблицу успешной приёмки.

## Повторение

Использовать стабильный Vite в изолированном checkout, не менять исходники во время
прогона. Playwright глобальный; установка новых browser/dependency не требуется.

```bash
PLAYWRIGHT_MODULE=/opt/codex/runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright/index.mjs \
CHROME_EXECUTABLE_PATH=/usr/bin/chromium \
node scripts/night-boss-ui-qa.mjs \
  --origin http://127.0.0.1:5536 \
  --save /tmp/chronoworld-night-baseline/saves/after-ch10_s18.json \
  --clock /tmp/chronoworld-night-baseline/saves/after-ch10_s18.clock.json \
  --stage ch10_s18 --width 390 --renderer webgl1 --telegram 1 \
  --render-every 6 --out /tmp/chronoworld-night-lord-qa
```

Для короткого устройства: `--width 360 --renderer canvas`, отдельный `--out`.
Для жука: stage `ch2_s10` и пара файлов `after-ch2_s10.json`/`.clock.json`.
Один прогон ограничен 240 с; изменить можно `--max-seconds`.
Сводка и SHA-256 источников/входных снимков:
[summary.json](../REPORTS/2026-10-05-night-boss-ui/summary.json).

## Повторная приёмка исправления

Продукционное исправление выполнено отдельным агентом в `BattleScene.ts` и новом
`battlePresentation.ts`; core/data/assets не менялись. Масштаб ограничен union bbox
зарегистрированных анимаций, крупные тела разведены отдельной display-проекцией,
стопы/полосы/эффекты остаются вместе. Rectangle ввода следует реальным idle/walk/hurt
bbox и отражению. У Владыки scale `3.2 → 2.0`; масштаб обычных фигур не увеличивается.
