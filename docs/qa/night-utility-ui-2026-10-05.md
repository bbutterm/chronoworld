# Компактные служебные экраны — 05.10.2026

Пакет ограничен почтой, заданиями, достижениями и лавкой. Общие компоненты окна, навигации,
прокрутки, валютной шапки и Telegram Back используются из отдельного проверенного пакета.
Боевая логика, баланс, сохранения, новая графика и пороги бюджетов не меняются.

## Воспроизведённые проблемы

- В почте, заданиях и достижениях маска списка и «Забрать всё» сохраняли старую нижнюю границу
  после изменения Telegram safe/content insets. Строки уходили под навигацию.
- Лавка использовала неподвижную сетку четыре на два. В Telegram 360×640 последняя строка
  располагалась ниже доступной области, а прокрутки товаров не было.
- Перезапуск сцены после получения награды, раскрытия списка и покупки сбрасывал открытое
  окно, прокрутку и объекты сцены. Обновление без перезапуска требовало отдельного обновления
  общей валютной шапки.
- Подтверждение покупки держало снимок товара. Для слота с двумя единицами повтор старого
  подтверждения мог относиться уже ко второй единице; смена дня и обновление лавки также
  должны завершать срок этого подтверждения.

Исходные замеры выполнены в настоящих сценах с законным поздним сохранением. На 360×640
списки оставались на прежней границе при изменении суммарного верхнего inset 136→216 CSS px;
в лавке не было ScrollArea. Ранние диагностические снимки с незавершённой анимацией и неверно
выбранной активной сценой исключены из доказательства.

## Изменения

Списки и единственное действие получения используют текущую безопасную нижнюю границу.
Перерисовка содержимого сохраняет тот же ScrollArea, раскрытые полученные строки и доступную
прокрутку. Resize ограничивает offset только тогда, когда список иначе показывал бы пустую
область. Получение наград обновляет общую шапку через `refreshScreen`, без ручных событий
viewport и без `Scene.restart`.

На компактных экранах лавка показывает две колонки с обычным размером текста и прокруткой
всех восьми товаров. Подтверждение привязано к дню, числу обновлений, товару, цене и уже
купленному количеству. Старое подтверждение не списывает ресурсы повторно; заново открытая
покупка следующей единицы остаётся доступной. Отдельные награды и «Забрать всё» проверяют
актуальное состояние перед записью.

Заголовки строк получают до двух строк. Прогресс и награды разделены по высоте, кнопки не
уменьшаются. Общая адаптивная политика включает эти сцены только после фактической приёмки;
её исходник принадлежит отдельному пакету интерфейса.

## Приёмка

Стенд `scripts/night-utility-ui-qa.mjs` запускает настоящий Phaser в локальном Chromium.
Проверяются Canvas fallback и WebGL, Telegram 360×640 и 390×844. SDK моделирует отдельные
safe/content insets и одну физическую кнопку Back. Изменение insets и высоты проверяется
при открытых письме и товаре, а также в прокрученных списках.

Сохранения берутся из законных полных прохождений: ранний и средний snapshot включены
в каталог отчёта, поздний — существующий `tests/fixtures/boot-late-save.json`. Ранний бой,
48 часов ожидания среднего профиля, офлайн-награда и пять повторов кампании выполняются
публичными действиями ядра. День браузера начинается с часов соответствующего аккаунта
и продвигается на реально прошедшее время; полностью замороженный `Date.now` не используется,
потому что Phaser рассчитывает анимации по нему. Стенд не меняет валюты, статистику или
флаги получения ради нужного результата.

Действия выполняются физическими касаниями и прокруткой. Проверяются получение одного
письма и всех вложений, подтверждение/отмена удаления, награда задания, порога активности,
достижения, оба «Забрать всё», доступная покупка товара с stock=2, недоступная покупка,
бесплатное/платное обновление и отмена обновления. Двойные касания сравниваются с результатом
одного публичного действия ядра. Раскрытие полученных строк и достижение последней строки
проверяются отдельными утверждениями, а не наличием скриншота.

Каждое изменение геометрии проверяет identity сцены, ScrollArea и открытого окна, отсутствие
повторного `create`, сохранность раскрытого списка, точное ограничение offset, неизменность
байтов сохранения и числа записей. Реальные размеры текста и hit areas рассчитываются через
матрицы предков и масштаб холста: не менее 12 CSS px и 44 CSS px соответственно.

Стенд разрешает только локальные GET/HEAD. Telegram SDK подменён пустым локальным ответом;
облачные записи и внешние запросы не выполняются. Для compiled-сборки приватный ответ JS
получает только QA-ссылки на game/view; файл сборки и игровое поведение не меняются.

```bash
PLAYWRIGHT_MODULE=/opt/codex/runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright/index.mjs \
CHROME_EXECUTABLE_PATH=/usr/bin/chromium \
node scripts/night-utility-ui-qa.mjs
```

Для общего CPU-окна SIGTERM стенда либо файл `stop` в `QA_OUT` останавливает следующий ввод
после завершения текущего действия. Контекст и браузер закрываются, JSON остаётся с
`passed: false` и отдельной причиной остановки; прерванный профиль не объявляется пройденным.
`progress.json` сохраняет уже законченные контексты. Перед новым полным запуском файл
остановки удаляется или выбирается новый каталог.

Для локальной production preview после включения сцен в общей адаптивной политике:

```bash
npm run build
QA_PREVIEW=1 \
PLAYWRIGHT_MODULE=/opt/codex/runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright/index.mjs \
CHROME_EXECUTABLE_PATH=/usr/bin/chromium \
node scripts/night-utility-ui-qa.mjs
```

Проверка геометрии и защиты действий: новые десять содержательных тестов. Финальный явно
перечисленный набор вместе с существующими inbox/shop/shop-events/UI-lint проверками
прошёл 53/53 теста в шести файлах. Ранее также прошёл исторический набор 46 тестов;
финальные цифры берутся из нового машинного JSON-отчёта. Typecheck и проверка синтаксиса
стенда проходят; бюджеты и UI-lint baseline не увеличены.

```bash
npm run typecheck
npx vitest run tests/utility-screen-layout.test.ts tests/utility-screen-actions.test.ts \
  tests/inbox-rows.test.ts tests/shop.test.ts tests/shop-events-ui.test.ts tests/ui-lint.test.ts \
  --maxWorkers=1
node --check scripts/night-utility-ui-qa.mjs
```

DEV и compiled проверка обе завершили матрицу 20/20: два renderer × два телефона × пять
законных профилей. Собранная игра проверена в 164 состояниях, с 120 действиями и 32 проверками
dynamicInsets/resize. Минимальные фактические размеры — 12 CSS px для текста и 44 CSS px для
нажатия; runtime errors, invalid frames и внешних запросов — ноль.

Compiled приёмка использует приватный read-only файл политики от владельца общего интерфейса:
SHA `0572a4acb6240fbb27bd3be401ecea43e4e216fe61578ec57483462d7bea8574`.
Он включает восемь уже разрешённых root-сцен и ровно эти четыре сцены. Файл не входит
в пакет Utility; включение в production выполняет владелец общей политики. Собранный
`index-DxT3NsMR.js` имеет SHA `80a176467ad993e01cf8a58562546f1a2302f4e3871cd5c510309755e13a0bf0`.

Итог `production-summary.json` выбирает восемь завершённых профилей из первоначального
compiled запуска, два новых Canvas390 и десять новых WebGL. Первоначальный общий отчёт
остался `passed: false` из-за согласованной остановки между действиями для CPU-окна root;
его частичный девятый профиль исключён. Все выбранные контексты имеют одинаковые SHA
игрового кода, зависимостей, сборки и стенда. DEV итог также сохраняет первоначальную
ошибку слишком ранней проверки Back; исправлено ожидание целевой сцены в стенде, после чего
все пять WebGL390 профилей выполнены заново с теми же продуктовыми исходниками.

Основная матрица использует reduced motion для проверки устойчивой геометрии. Отдельный
normal-motion запуск выбирается `QA_REDUCED_MOTION=0`; ожидание 1400 мс перед измерением
даёт завершиться полёту награды и счётчику валюты. Это ожидание теста, а не норматив скорости
игры. Четыре дополнительных compiled-профиля прошли: Canvas360 welcome, WebGL390 mid,
WebGL390 achievements и отдельный контроль позднего второго касания refresh. Всего —
33 состояния, 31 действие и шесть изменений окна, без runtime errors и invalid frames.

Первый normal-motion WebGL запуск остановился на поиске «Отмена»: диагностический повтор
показал, что предыдущее второе касание уже открыло платное подтверждение, а следующий ввод
по кнопке под ним закрывал его через фон. Исторические native timestamps отсутствуют,
поэтому точный интервал старых касаний не объявляется измеренным. После добавления пассивного
лога pointer events обычный повтор прошёл с интервалом 188,2 мс и без лишнего подтверждения.
Контроль с намеренно поздним вторым refresh-касанием получил реальный интервал 726,1 мс,
открыл допустимое платное подтверждение; отмена оставила сохранение и валюты неизменными.
Стенд разрешает такой переход только при измеренном интервале ≥400 мс, вне существующего
input shield. Затем новое платное подтверждение и его отмена также проверены.

Два прежних normal-motion отчёта сохраняют FAIL. Исправлены ожидания стенда для уже открытого
подтверждения и добавлены диагностические опции; продуктовые исходники и общие зависимости
между всеми запусками не менялись. Отдельный `motion-summary.json` хранит результаты,
первоначальные ошибки и SHA каждой версии стенда.

Компактные отчёты, законные fixtures и пять исходных PNG собранной игры находятся в
`docs/REPORTS/2026-10-05-night-utility-ui/`. В `raw/` включены десять полных входных JSON,
сжатых детерминированным gzip; 3,26 MB исходных данных занимают 133 KB. Исходные SHA,
PASS/FAIL и причина остановки сохранены в `raw/index.json`; данные читаются через
`gzip -dc`, без зависимости от временных каталогов. Точные SHA разрешённых файлов и
окончательный статус пакета перечислены в `READY.json`; общие read-only файлы в него
не включаются. Полный `npm run check` выполняется владельцем root после интеграции.

Это проверка поведения и геометрии веб-интерфейса. Она не измеряет FPS физического iPhone.
Существующий долг первоначальных спрайтов 6 337 211 байт при бюджете 3 MB данным пакетом не закрывается.
