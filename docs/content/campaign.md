# Кампания и офлайн-сундук

Кампания — это JSON-файлы глав в `data/campaign/`. Код трогать не нужно: игра подхватывает новые главы сама.

```
data/campaign/<глава>.json   глава: этапы по порядку
data/units/mob_*.json        монстры и боссы (kind monster / boss)
data/skills/mob_*.json       ульты монстров
data/progression.json        campaign.enemyStatGrowthPerStage, campaign.replayRewardMultiplier, offline.capHours
```

## Формат главы

```json
{
  "$schema": "../schema/chapter.schema.json",
  "id": "chapter1",
  "name": "Глава 1. Зелёные луга",
  "order": 1,                                  // порядок глав в кампании
  "stages": [
    {
      "id": "ch1_s1",                          // уникален по всей кампании
      "name": "Луг у деревни",
      "boss": false,                           // true — босс-этап (нужен юнит kind boss)
      "enemies": [                             // ровно 5 слотов: 0–1 фронт, 2–4 тыл
        { "unit": "mob_fast", "mult": 0.6 },   // mult — множитель hp/atk/def (по умолчанию 1)
        null,
        { "unit": "mob_drops" },
        null,
        null
      ],
      "rewards": { "jobExp": 40, "gold": 50 },           // за победу; jobExp — каждому герою отряда
      "offlinePerMinute": { "jobExp": 2, "gold": 5 }     // доход сундука, пока это последний пройденный этап
    }
  ]
}
```

Этапы всех глав склеиваются в одну цепочку по `order`, у каждого этапа есть сквозной номер `globalIndex` (с 0).

`mult` босса — **0.67** (подобран прогоном): отряд из теста (Мечник / Лучник / Аколит, джоб 4 к этапу 10) побеждает
**79%** боёв (1000 seed'ов, сохранение — как в `tests/chapter1-playthrough.test.ts` перед первой попыткой этапа 10),
бой ~39 с из 90. Кривая крутая: `mult` 0.64 → 97%, 0.70 → 49%, 0.76 → 5%. Этапы 1–9 тот же отряд перед первой
попыткой проходит в 100% боёв (по 300 seed'ов). Другие составы на боссе: Мечник / Маг / Аколит — 62%,
Вор / Лучник / Аколит — 70%; без Аколита (Мечник / Лучник / Маг) этап 9 — 80%, босс — 0%. Меняя босса, свиту или
этапы перед ним (от них зависит джоб отряда) — перемерить.
В бою босс-этапа — баннер «ИМЯ · Босс главы» (~1.5 с, часы боя стоят) и полоска HP босса наверху.
Герой орков (`mob_boss1`) остался в контенте — для Башни и будущих глав.
Старт — три Новичка (`progression.heroes.count`), 4-й и 5-й герои приходят после боссов глав 1 и 2 (`heroes.recruits`). Этапы 1–4 — Новички; Новичку опыт считается своей кривой (`progression.exp.byTier["0"]`), так что к концу этапа 4
все герои на джобе 10: на итогах вместо «Дальше» — «Профессия ›», экран выбора идёт по всем готовым героям подряд (или Герои → карточка → «Сменить профессию»). Этапы 5–10 — первые профессии.

Проверка, что глава проходится с нуля: `npx tsx scripts/playthrough.ts` (ядро, по этапам: попытки, уровни, смена профессии),
`node scripts/e2e-chapter1.mjs` (то же через интерфейс в браузере), тест `tests/chapter1-playthrough.test.ts`.

## Открытие этапов и награды

- Первый этап кампании открыт сразу; каждый следующий открывается, когда пройден предыдущий (по `globalIndex`, в том числе через границу глав).
- Победа при первом прохождении — награда целиком, этап отмечается пройденным, открывается следующий.
- Повтор пройденного этапа — награда × `replayRewardMultiplier` (с округлением вниз).
- Поражение — ничего, кроме счётчика боёв.

## Рост силы врагов

Статы монстра на этапе:

```
hp/atk/def = база из data/units × mult × (1 + enemyStatGrowthPerStage) ^ globalIndex   (округление до целого)
spd, moveSpeed — без изменений
```

При `enemyStatGrowthPerStage = 0.08` враг 10-го этапа (globalIndex 9) сильнее базового в 1,08⁹ ≈ 2 раза. Поэтому монстров описываем «базовыми», а сложность конкретного этапа задаём составом и `mult`.

## Офлайн-сундук

- Доход в минуту — `offlinePerMinute` последнего пройденного этапа (с максимальным `globalIndex`); пока ничего не пройдено — ноль.
- Копится не дольше `offline.capHours` часов. Если часы устройства переведены назад — ноль.
- Сбор: золото в ресурсы, джоб-опыт — **каждому** герою (не только отряду), таймер сбрасывается.

## Как добавить главу

1. Скопировать `data/campaign/chapter1.json` в `data/campaign/chapter2.json`, поменять `id`, `name`, `order: 2`.
2. Дать этапам новые id (например, `ch2_s1` …) — повтор id с другой главой — ошибка.
3. Расставить врагов: только юниты `kind: monster` или `boss`, в этапе хотя бы один враг; у `boss: true` — хотя бы один босс.
4. Новый монстр: `npm run content:new -- unit mob_xxx --from mob_melee` (спрайт — id из `assets/sprites/sprites.json`).
5. `npm run content:check` — проверит схему, ссылки и правила выше; `npm test` — что этапы играются.

Все числа в главе 1 и у монстров — заглушки до баланса.
