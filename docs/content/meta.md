# Пресеты отряда, экспедиции, достижения (K8, K9, K10)

Ядро — `src/core/meta/`, всё чистые функции без часов и случайности: день (`'YYYY-MM-DD'`), время (мс) и seed
передаёт UI. Интерфейс: экраны «Отряд», «Экспедиции», «Достижения» (src/game/scenes).

```
data/expeditions.json   экспедиции по локациям (K9) + лимиты пресетов (K8, временно здесь)
data/achievements.json  достижения (K10)
src/core/meta/          config, errors, formation, expeditions, achievements
src/core/save/migrate-expeditions.ts   миграция сохранения v5 → v6 (доска поручений → экспедиции)
```

## Контекст

```ts
import expeditionsJson from '../../data/expeditions.json';
import achievementsJson from '../../data/achievements.json';
const mctx = withMeta(featureCtx, expeditionsJson, achievementsJson); // битый конфиг → MetaError('invalid_config')
```

`withMeta` сохраняет тип исходного контекста (можно передать `FeatureContext` с башней и экипировкой).
Авто-расстановке нужен `FeatureContext` (мощь героев, K2).

Все ошибки — `MetaError` с полем `code` и русским `message` для игрока.

## Сохранение v3

`SAVE_VERSION = 3`, миграция `MIGRATIONS[2]` добавляет:

| Поле | Умолчание | Что это |
| --- | --- | --- |
| `presets` | `[]` | пресеты отряда `{ id, name, squad: (id \| null)[5] }` |
| `bounties` | пустая доска | в v3–v5 — доска поручений (`board`, `lastRefreshDay`, `refreshesUsed`, `active`); с v6 — экспедиции (раздел K9, «Сохранение v6») |
| `achievements.counters` | см. ниже | счётчики достижений |
| `achievements.claimed` | `[]` | id полученных достижений |

При миграции счётчики-«максимумы», видные из сохранения, засчитываются сразу: `stages_cleared` (число пройденных
этапов), `tower_floor`, `hero_max_job_level` (включая уровни пройденных профессий). Накопительные — с нуля.

## K8. Пресеты и авто-расстановка

```json
"presets": { "max": 5, "nameMaxLength": 20 }
```

- `savePreset(save, name, mctx, { id?, squad? })` → `{ save, preset }`. Без `id` — новый пресет `p<N>`
  (N — наибольший номер + 1), с `id` — перезапись. `squad` по умолчанию — текущий отряд.
  Ошибки: `invalid_preset_name`, `preset_limit`, `unknown_preset`, `invalid_squad`, `unknown_hero`.
- `applyPreset(save, id)` — ставит отряд; пропавшие герои → пустые слоты. `deletePreset(save, id)`.
- `autoFormation(save, ctx)` → новый `squad` (save не меняет; применить — `{ ...save, squad }`):
  1. 5 самых сильных героев по `heroPower` (с экипировкой, если в контексте есть `equipment`); при равной
     мощи — по id героя;
  2. «передние» — танки (роль профессии `tank`), затем ближний бой (обычная атака `range: melee`) — занимают
     слоты 0, 1, 2… по порядку; «задние» — лекари (`healer`), затем дальний бой — с конца: 4, 3, 2…
     Итог: танки в 0–1, лекари в самом тылу, при нехватке группы соседняя занимает её слоты.

## K9. Экспедиции по локациям

Заменили доску поручений (отзыв владельца: «отправка на поручения максимально неудобна»; выбран вариант «экспедиции по
локациям»). Не копия AFK: нет доски, редкостей, ролей, обновлений и ручного выбора героев.

### Как играется

1. Локации (места Ragnarok Online) открываются по этапам кампании. Закрытая — на экране с замком и «Откроется на этапе 2-6».
2. На карточке локации игрок выбирает срок (1 / 4 / 8 ч, выбор общий и запоминается) и жмёт «Отправить» — одно нажатие.
3. Отряд собирает ядро (`autoParty`): до 5 свободных героев, пока сумма мощи не достигнет порога локации. Ни ролей, ни
   редкостей — только «Мощь N / нужно M». Не хватает — кнопка серая, строка красная.
4. На локации — одна экспедиция, герой — в одной экспедиции. **Герои в экспедиции продолжают сражаться** (кампания, башня,
   охота) — экспедиция занимает только «слот экспедиции» героя. Героя в экспедиции нельзя отдать в корм вознесения
   (`fodderBlocker`, heroes/merge.ts).
5. Вернулись — «Забрать» на карточке или «Забрать всё» сверху. Добыча бросается при отправке и хранится снимком, находки
   показываются по возвращении.

### Кого берёт автоподбор

Решение по подсказке владельца «сначала не из основного отряда»: в этой игре герои экспедиции сражаются как обычно, а
запасные карточки — корм вознесения, который экспедиция блокирует. Поэтому очередь такая:

1. кого нельзя отдать в корм — основной отряд, сюжетные карточки, закреплённые замком;
2. запасные карточки без копий;
3. запасные карточки, у которых есть копия (вероятный корм), — последними.

Внутри очереди — по убыванию мощи до порога; не хватило при полном отряде — слабейшего меняет сильнейший из оставшихся.
Затем лишние убираются, а каждый участник заменяется самым слабым свободным героем не дальней очереди, если порог всё равно
набирается: сильные герои остаются для трудных локаций. Всё детерминировано; при равной мощи — порядок героев в сохранении.
Проверено моделью баланса: при обратной очереди (сначала запас по мощи) экспедиции держали копии фиолетовых карточек,
вознесения до золотой не случались, и казуал (2 сессии) не проходил главу 3 за неделю.

### Данные (`data/expeditions.json`)

```json
{
  "maxHeroes": 5,
  "durations": [{ "hours": 1, "bonus": 0 }, { "hours": 4, "bonus": 0.1 }, { "hours": 8, "bonus": 0.2 }],
  "locations": [
    { "id": "ant_hell", "name": "Муравейник", "description": "…", "stage": "ch1_s8", "power": 800,
      "tint": "#9a6a32", "monster": "mob_elite", "monsterScale": 0.6,
      "perHour": { "gold": 45, "jobExp": 60 },
      "loot": [
        { "kind": "item", "chance": 0.012, "items": ["sandals", "shoes", "cotton_shirt", "adventurers_suit", "bandana", "cap"] },
        { "kind": "gems", "chance": 0.12, "count": 3 },
        { "kind": "heroCard", "rarity": "blue", "chance": 0.002, "count": 1 }
      ] }
  ]
}
```

| Поле | Что это |
| --- | --- |
| `durations[].hours`, `bonus` | срок и надбавка к добыче: **часы добычи = часы × (1 + bonus)** — 1 ч → 1, 4 ч → 4.4, 8 ч → 9.6 (длинные чуть выгоднее в час) |
| `stage` | этап, после первой победы на котором локация открыта |
| `power` | порог суммы мощи отряда (`heroPower` с экипировкой) |
| `tint`, `monster`, `monsterScale` | «картина» карточки, пока нет арта локаций: цвет места и фигура монстра (id из `data/units`) |
| `perHour` | золото и опыт (в общий пул) за час добычи, `round(perHour × часы добычи)` |
| `loot[]` | находки: бросок за каждый целый час добычи с шансом `chance` (дробный остаток — бросок с шансом × остаток). `item` — предмет из `items` (тема места, равновероятно), `gems` / `scrolls` — `count` штук, `heroCard` — карта случайного героя редкости `rarity` (blue/purple; герой выбирается при получении). Герои v2: осколков нет — прежние «осколок N%» ниже заменены картами героя (≈ N/30 %), `docs/design/heroes-v2.md`, раздел 0 |

Проверки: схема (`ExpeditionsConfigSchema`, `data/schema/expeditions.schema.json`), `validateExpeditions` (этап, монстр,
предметы существуют), content:check предупреждает, если порог выше рекомендуемой мощи самых трудных этапов до открытия.

### API (`src/core/meta/expeditions.ts`)

- `expeditionStatus(save, now, ctx)` → карточки для экрана по порядку конфига: `{ location, unlocked, lockedText, active
  (с remainingMs, done) | null, party (PartyPick для свободной открытой) | null }`.
- `autoParty(save, locationId, ctx)` → `{ heroIds, power, need, ok }`; порог недостижим — `ok: false`, `heroIds: []`,
  `power` — наибольшая мощь пятёрки свободных героев.
- `startExpedition(save, locationId, hours, now, ctx, heroIds?)` — без `heroIds` отряд — `autoParty` (так делает UI).
  Ошибки `MetaError`: `unknown_location`, `location_locked`, `location_busy`, `invalid_duration`, `not_enough_power`,
  ручная группа — `too_many_heroes`, `duplicate_hero`, `unknown_hero`, `hero_busy`. `endsAt = now + hours`.
- `rollExpeditionLoot(loc, hours, seed, ctx)`, `expeditionSeed(save, locationId, startedAt)` = `lootSeed('expedition',
  createdAt, локация, startedAt)`; `expectedExpeditionLoot(loc, hours, ctx)` — средние (подписи на карточке).
- `claimExpedition(save, locationId, now, ctx)` — при `now ≥ endsAt` (`expedition_not_finished`, `expedition_not_running`):
  золото, гемы, опыт в пул, карты случайных героев (новые экземпляры), свитки, предметы в инвентарь (предмета больше нет в игре — пропадает).
  Герои свободны, `bounties_done + 1`, событие `expeditionDone`. Локацию убрали из конфига — начатую всё равно можно забрать.
- `claimAllExpeditions(save, now, ctx)` — все вернувшиеся (порядок конфига); обёртки `actClaimExpedition`,
  `actClaimAllExpeditions` (день — для счётчиков).
- `finishedExpeditions`, `idleExpeditions` (открытые свободные, куда хватает мощи), `busyHeroes`; значок главной —
  `expeditionsBadgeCount` (src/game/flow.ts) = вернувшиеся + простаивающие локации.

Id функции в `data/unlocks.json` (`bounties`), счётчик достижений (`bounties_done`) и ключ сохранения (`bounties`) оставлены
прежними — они лежат в сохранениях.

### Экран (`ExpeditionsScene`, ключ `Expeditions`)

Сверху «Забрать всё (N)» (золотая и пульсирует, пока есть вернувшиеся) и подпись «Отряд собирается сам · герои в экспедиции
продолжают сражаться». Ниже карточка на каждую локацию: слева «картина» (градиент цвета места, свечение, фигура монстра;
закрытая — затемнена), справа название, описание и состояние:

- свободна: «Мощь N / нужно M» (зелёная или красная), лица отряда автоподбора, сроки «1 ч / 4 ч / 8 ч», «Отправить»,
  строки «≈ 432 зол. · 576 опыта за 8 ч» и «Находки: гемы ≈3, осколки, снаряжение»;
- в пути: «В пути · 8 ч», отсчёт, полоса, золото и опыт, «Находки — по возвращении»;
- вернулась: светлая карточка, «Отряд вернулся!», добыча и находки, пульсирующая «Забрать»;
- закрыта: замок, «Откроется на этапе 2-6», нужная мощь и что там можно найти.

Плитка главной «Экспедиции» (id функции `bounties`): «Вернулись: N» / «В пути: N» / «Отправьте отряд», красный кружок —
`expeditionsBadgeCount`. Имена объектов для e2e: `claimAll`, `send_<локация>`, `claim_<локация>`, `hours_<локация>_<часы>`.

### События в пути — «текстовые приключения»

Дизайн — `docs/design/expedition-adventures.md`. Данные — `data/expedition_events.json` (схема
`src/core/meta/expedition-events-schema.ts`, файл необязателен: нет — экспедиции без событий), ядро —
`src/core/meta/expedition-events.ts`, окно — `src/game/expeditionEventModal.ts`.

1. При отправке выпадают события: 1 ч — одно, 4 ч — два, 8 ч — три (`perExpedition`); свои события локации — с весом
   `localWeight` (2), общие — 1. Сейчас 48 событий: по 4 на каждую из 10 локаций и 8 общих.
2. Событие ждёт решения, когда `now ≥ at`; на карточке — кнопка «Событие (N)» (`event_<локация>`), окно — варианты
   (`choice_<id>`), под вариантом — кто из отряда подходит (портрет, «надёжно»), «Нужен вор — без него шанс 35%» или «Шанс N%».
   Выбор бросается сразу (`chooseExpeditionEvent`) и хранится; не решил до «Забрать» — вариант по умолчанию.
3. Награда исхода — ступень `tiers` от «куска» (снимок золота/опыта экспедиции ÷ число событий): small 0.12, medium 0.24,
   big 0.4, loss −0.1; плюс предмет из первого (обычного) списка добычи локации, редко гемы. Вариант по умолчанию добычу не
   меняет. Разумный выбор ≈ +16% золота и опыта (тест `tests/expedition-events.test.ts`), по умолчанию — 0%.
4. «Забрать» — окно-рассказ (событие, выбор, исход, добыча). Летопись экспедиций (кнопка «Летопись», `expChronicle`) —
   `bounties.journal`, «сблизились» — `bounties.bonds` (по 40 последних).
5. Сохранение — без смены версии: `bounties.active[].events?`, `bounties.journal?`, `bounties.bonds?` необязательны;
   экспедиции из старых сохранений — без событий. id событий лежат в сохранениях — не переименовывать.

Значок «событие ждёт» для плитки/навигации — `pendingExpeditionEvents(save, now)` (в `expeditionsBadgeCount` пока не
подключён).

### Сохранение v6

`SAVE_VERSION = 6`. `save.bounties = { active: ActiveExpedition[] }`, где экспедиция — `{ location, hours, heroIds, power,
startedAt, endsAt, rewards: { gold, jobExp, gems, shards, scrolls, items } }`.

Миграция v5 → v6 — отдельная функция `migrateBountiesToExpeditions` (`src/core/save/migrate-expeditions.ts`, шаг
`MIGRATIONS[5]`): доска, обновления и поручения в работе убираются, все герои свободны; награда всех поручений в работе
(завершённых и нет — времени миграция не знает) приходит письмом «Поручения стали экспедициями» (золото, гемы, опыт;
осколки — гемами, 5 за осколок: у письма нет осколков); одно сообщение игроку (`notices`). Поручений в работе не было — ни
письма, ни сообщения. `src/core/heroes/migrate.ts` (v3 → v4) не менялась.

**Следующая миграция** (например, героев) — новый шаг `MIGRATIONS[6]` (v6 → v7) и `SAVE_VERSION = 7`; эту функцию не
трогать. Если два шага нужно выпустить одной версией — композиция в `MIGRATIONS[5]`:
`(old) => другойШаг(migrateBountiesToExpeditions(old))` (поле `version` выставляет последний шаг).

## K10. Достижения

```json
{ "id": "tower_5", "name": "Восхождение", "description": "Поднимитесь на 5 этаж башни",
  "counter": "tower_floor", "target": 5, "rewards": { "gems": 20 } }
```

`rewards`: `gold`, `gems` — в ресурсы, `jobExp` — в общий пул опыта героев, `shards` — осколки «отстающему» сюжетному герою
(`shardTarget`); пропущенные — 0.

| Счётчик | Режим | Где считается |
| --- | --- | --- |
| `stages_cleared` | max | число пройденных этапов — после `actPlayStage`/`actSkipStage` и др. |
| `tower_floor` | max | `save.tower.floor` — после `actClimbTower` |
| `summons` | add | `actSummon` (по числу карточек) |
| `ascensions` | add | `actAscend` |
| `items_equipped` | add | `actEquip` (каждое надевание) |
| `bounties_done` | add | `claimExpedition` (id исторический — раньше поручения) |
| `battles_won` | add | победы в `actPlayStage`, `actSkipStage`, `actClimbTower` |
| `hero_max_level` | max | наибольший уровень карточки героя — после любых act* и наград (v4; в старых сохранениях был `hero_max_job_level`, миграция переносит) |

- `trackAchievement(save, key, value, mode?)` — `add` копит, `max` хранит максимум (без `mode` — режим из таблицы).
- `syncAchievementCounters(save)` — обновить все «максимумы» из состояния сохранения.
- `achievementStatus(save, mctx)` — список с `progress` (≤ target), `done`, `claimed`.
- `claimAchievement(save, id, mctx)` — награда один раз. Ошибки: `unknown_achievement`, `achievement_not_done`,
  `achievement_already_claimed`.

Функции ядра (`playStage`, `climbTower`, `equip`…) о достижениях не знают — считают только обёртки `act*`,
поэтому UI должен вызывать именно их.

## Охота на MVP (`data/hunt.json`, `src/core/hunt`)

Дизайн и числа — `docs/design/mvp-hunt.md`. Коротко: MVP дня из RO (7 в недельной ротации, `bosses[номер дня mod 7]`),
у каждого стихия, слабость, фазы, свита и заряд; 2 попытки в день, бой 45 с с ручной ультой. MVP падает за бой: уровень
охотника (`mvp.ranks`, 15) — победа выше (быстрая — прыжок), поражение ниже; можно биться ниже своего уровня. Результат —
доля снятых ОЗ уровня × урон порога уровня; награда — высший порог `tiers` (как раньше). Герои стихии слабости — АТК ×2,
прочие — ×0.85. Победа («MVP!») — шанс карты MVP 12% с гарантией на 10-й победе; карта вставляется в предмет своего слота
(InventoryScene) навсегда, бонус — доли базовых статов героя.

API (`src/core/hunt/hunt.ts`): `huntStatus(save, day, ctx)` (MVP, уровень, подсказка героев стихии, лучший результат),
`fightHunt(save, day, ctx, { rank? })` (ctx.combat.player — ручная ульта сцены), `sweepHunt`, `huntBoss(day, ctx, rank)`,
`huntRank`, `huntScore`, `huntSquad` (множители стихии); карты — `src/core/equipment/cards.ts`: `insertCard`,
`cardsForItem`, `ownedCards`, `heroCardStats`. Сохранение без смены версии: `hunt.level`, `hunt.kills`, `hunt.cards`,
`hunt.dry`, у предмета `card` — всё необязательное; старые рекорды (`best`, в том числе старые id боссов) задают уровень.
