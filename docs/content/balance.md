# Инструмент баланса

`npm run balance` — «виртуальный игрок» играет полный цикл игры несколько игровых дней: кампания, башня испытаний, экипировка, быстрые награды, ежедневные задания, поручения, достижения. Всё считается функциями ядра — обёртками `act*` (`actClaimOffline`, `actUseFastRewards`, `actPlayStage`, `actClimbTower`, `actChangeJob`, `actEquip`), поэтому задания и счётчики достижений засчитываются так же, как в игре. Бои — настоящим симулятором. Правила игры в скрипте не повторяются: поменяли данные в `data/*.json` — перезапустили — увидели эффект.

Все числа в данных — заглушки. Инструмент **измеряет** форму прогрессии и экономики, а не подгоняет её.

## Запуск

```
npm run balance                                  14 дней, 4 сессии в день, CSV в balance.csv
npm run balance -- --days 30                     30 дней
npm run balance -- --sessions 2                  2 сессии в день («казуал»)
npm run balance -- --days 7 --out /tmp/b.csv     другой путь для CSV
```

Результат детерминирован: одинаковые данные и модель → одинаковый CSV и сводка. 14 дней считаются примерно за секунду. `balance.csv` лежит в корне и в git не попадает — откройте его в Google Таблицах/Excel и постройте графики.

Контекст собирается так же, как в UI: `withFeatures` → `withEquipment` → `withTower` → `withMeta` из `data/progression.json`, `data/quests.json`, `data/items/*.json`, `data/drops.json`, `data/tower.json`, `data/bounties.json`, `data/achievements.json` (`loadFullContext()` в `scripts/lib/player-model.ts`).

## Модель игрока

Конфиг — `PLAYER_MODEL` в `scripts/lib/player-model.ts`:

| Поле | По умолчанию | Смысл |
| --- | --- | --- |
| `sessionsPerDay` | 4 | сессий в день (флаг `--sessions`) |
| `firstSessionHour` | 8 | час первой сессии дня |
| `hoursBetweenSessions` | 4 | часов между сессиями (8, 12, 16, 20 ч; ночь — остаток суток) |
| `maxLossesPerSession` | 3 | после стольких поражений в кампании игрок переходит к башне |
| `towerMaxAttemptsPerSession` | 10 | штурмов башни за сессию не больше… |
| `towerMaxLossesPerSession` | 2 | …и поражений в башне не больше |
| `fastRewardsPerDay` | 1 | сколько раз в день брать быстрые награды: сначала бесплатные, затем за гемы (если хватает) |
| `bounties` | true | отправлять героев на поручения |
| `roleByHero` | tank, tank, damage, damage, healer | желаемая роль героя h1…h5 при смене профессии |
| `seedBase` | 1 | seed боя = `seedBase + save.battleSeq`; seed доски поручений = `seedBase` |
| `startDate` | 2026-01-01 | календарная дата дня 1 (дни — строки `YYYY-MM-DD`) |

Одна сессия (время сессии = `now`, день = `startDate + (day − 1)`):

1. Забрать офлайн-сундук (`actClaimOffline`), забрать завершённые поручения (`claimBounty`).
2. Быстрые награды (`actUseFastRewards`), пока за день использовано меньше `fastRewardsPerDay`.
3. Забрать всё готовое: награды заданий (`claimQuest`), пороги активности (`claimActivity`), достижения (`claimAchievement`) — по кругу, пока что-то появляется.
4. **Подготовка** отряда:
   - смена профессии всем, у кого есть переход (`actChangeJob`): первая по алфавиту профессия с ролью из `roleByHero`, иначе первая по алфавиту из доступных;
   - экипировка (`actEquip`): каждому герою (сначала отряд) надевается свободный предмет с наибольшим приростом `heroPower`, пока прирост > 0. Предметы с других героев не снимаются;
   - `autoFormation` — новая расстановка.
5. Кампания: бить следующий открытый этап (`actPlayStage`, с экипировкой и выпадением предметов). Победа — подготовка и следующий этап; поражение — повтор с новым seed. После `maxLossesPerSession` поражений — стоп.
6. Башня (если открыта): `actClimbTower` до `towerMaxAttemptsPerSession` штурмов или `towerMaxLossesPerSession` поражений. После победы — подготовка.
7. Поручения: `ensureBoard` на сегодня, затем поручения с доски по убыванию ценности (золото + 10 × гемы). Группа — свободные герои: сначала первый подходящий по роли, остальные по порядку id. Не хватает героев — поручение пропускается. Ручные обновления доски модель не делает.
8. Снова шаг 3 и подготовка.

Повторы пройденных этапов ради опыта, пропуск боёв (K7) и пресеты модель не использует.

## Колонки CSV

Одна строка — одна сессия, значения на **конец** сессии.

| Колонка | Смысл |
| --- | --- |
| `day`, `date`, `session` | день (с 1), его дата `YYYY-MM-DD`, номер сессии в дне |
| `time_h` | часы с начала игры (полночь дня 1) |
| `chapter` | глава `stage_reached` (если всё пройдено — последняя) |
| `stage_reached` | следующий открытый этап — там игрок остановился; `done` — кампания пройдена |
| `cleared_count` | сколько этапов пройдено всего |
| `attempts`, `wins`, `losses` | боёв кампании в сессии, из них побед / поражений |
| `tower_floor` | последний пройденный этаж башни |
| `tower_attempts` | штурмов башни в сессии |
| `gold`, `gems` | золото и гемы на руках |
| `items` | предметов в инвентаре (надетые + лежащие) |
| `squad_power` | мощь отряда — `squadPower` ядра (K2, с экипировкой) |
| `next_stage_power` | мощь врагов `stage_reached` — `stagePower` ядра; 0, если всё пройдено |
| `avg_job_level` | средний джоб-уровень героев отряда |
| `jobs` | профессии по слотам через `\|` |
| `quests_claimed` | всего получено наград заданий (накопительно) |
| `bounties_done` | всего выполнено поручений (накопительно) |

`squad_power` и `next_stage_power` считаются одной формулой (`data/progression.json → power`), их можно сравнивать напрямую. Мощь — оценка, исход боя показывают `wins/losses`.

## Сводка в консоли

- **Первое прохождение** каждого этапа всех глав: день, сессия, часы, сколько боёв ушло. Непройденные — с числом боёв.
- **Башня и кампания на конец дня**: этаж, число этапов, золото, гемы.
- **Стены (топ-3)**: этапы с самым долгим ожиданием в часах (от прохождения предыдущего этапа или от первой сессии).
- **Экономика**: доход и расход золота и гемов по источникам — `offline`, `fast_rewards`, `campaign`, `tower`, `bounties`, `quests` (задания + пороги активности), `achievements`. Сейчас единственный расход — гемы на платные быстрые награды; золото тратить некуда.
- **Сигналы** — короткие наблюдения по-русски (эвристики в `signals()`):
  - золото копится без расхода; гемы почти не тратятся (расход < ¼ дохода);
  - стены ≥ 12 ч (до трёх);
  - скачки мощи врагов между соседними этапами ≥ ×1.3 (по данным, без симуляции);
  - кампания пройдена раньше конца симуляции;
  - башня не открыта / стоит на одном этаже ≥ 3 дней / трудные этажи (≥ 4 штурмов; помечается, если все — босс-этажи) / пройдена до вершины;
  - ≥ 10 ненадетых предметов в инвентаре;
  - задания, ни разу не выполненные; верхний порог активности ни разу не взят;
  - один источник даёт ≥ 60 % золота;
  - следующий тир профессий не открыт (джоб-уровень и порог);
  - сколько достижений получено.

## Как читать «стены»

- В CSV: несколько строк подряд с одним `stage_reached`, `wins = 0`, `losses = maxLossesPerSession`.
- Сравните `squad_power` и `next_stage_power`: разрыв, который закрывается только офлайн-опытом, — долгая стена.
- В башне стены — этажи с большим числом штурмов (сигнал «Трудные этажи башни»); `tower_floor` в CSV растёт ступеньками.
- Скачок `squad_power` вместе со сменой `jobs` — смена профессии; сброс `avg_job_level` при этом нормален (`jobChange.resetJobLevel`). Скачок без смены профессии — обычно новый предмет.

## Что подкручивать

- **Модель игрока** — `PLAYER_MODEL` в `scripts/lib/player-model.ts` (частота сессий, терпение, быстрые награды за гемы, поручения, роли).
- **Игру** — только данные: `data/campaign/*.json`, `data/progression.json` (рост врагов, опыт, офлайн, быстрые награды, мощь, пороги профессий), `data/jobs/*.json`, `data/items/*.json` и `data/drops.json`, `data/tower.json`, `data/quests.json`, `data/bounties.json`, `data/achievements.json`. Код скрипта менять не нужно.
