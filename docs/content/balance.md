# Инструмент баланса

`npm run balance` — «виртуальный игрок» проходит кампанию несколько игровых дней. Всё считается функциями ядра (`newGame`, `claimOffline`, `playStage`, `availableJobChanges`, `changeJob`, `stageStatus`, `enemySquad`), бои — настоящим симулятором. Правила игры в скрипте не повторяются: поменяли данные в `data/*.json` — перезапустили — увидели эффект.

Все числа в данных — заглушки. Инструмент нужен, чтобы видеть форму прогрессии, а не для подгонки прямо сейчас.

## Запуск

```
npm run balance                                  5 дней, 4 сессии в день, CSV в balance.csv
npm run balance -- --days 10                     10 дней
npm run balance -- --sessions 2                  2 сессии в день («казуал»)
npm run balance -- --days 7 --out /tmp/b.csv     другой путь для CSV
```

Результат детерминирован: одинаковые данные и модель → одинаковый CSV. Работает за доли секунды. `balance.csv` лежит в корне и в git не попадает — откройте его в Google Таблицах/Excel и постройте графики.

## Модель игрока

Конфиг — `PLAYER_MODEL` в `scripts/lib/player-model.ts`:

| Поле | По умолчанию | Смысл |
| --- | --- | --- |
| `sessionsPerDay` | 4 | сессий в день (флаг `--sessions`) |
| `firstSessionHour` | 8 | час первой сессии дня |
| `hoursBetweenSessions` | 4 | часов между сессиями (8, 12, 16, 20 ч; ночь — остаток суток) |
| `maxLossesPerSession` | 3 | после стольких поражений игрок закрывает игру и ждёт |
| `roleBySlot` | tank, tank, damage, damage, healer | желаемая роль героя в слоте 1–5 при смене профессии |
| `seedBase` | 1 | seed боя = `seedBase + save.battleSeq` (каждый бой — свой seed) |

Одна сессия:

1. Забрать офлайн-сундук (`claimOffline`).
2. Сменить профессии всем, у кого есть переход: берётся первая по алфавиту профессия с ролью из `roleBySlot` для слота героя, если такой нет — первая по алфавиту из доступных.
3. Бить следующий открытый этап. Победа — сразу следующий этап (и снова проверка смены профессий). Поражение — повтор тем же отрядом с новым seed. После `maxLossesPerSession` поражений — конец сессии.

Отряд не переставляется, повторы пройденных этапов ради опыта модель не делает.

## Колонки CSV

Одна строка — одна сессия, значения на **конец** сессии.

| Колонка | Смысл |
| --- | --- |
| `day`, `session` | день (с 1) и номер сессии в дне |
| `time_h` | часы с начала игры (полночь дня 1) |
| `stage_reached` | следующий открытый этап — там игрок остановился; `done` — кампания пройдена |
| `cleared_count` | сколько этапов пройдено всего |
| `attempts` | боёв в этой сессии (`wins + losses`) |
| `wins`, `losses` | побед / поражений в сессии |
| `gold` | золото на руках (тратить пока некуда) |
| `squad_power` | сила отряда игрока (см. ниже) |
| `next_stage_power` | сила врагов `stage_reached` той же формулой; 0, если всё пройдено |
| `avg_job_level` | средний джоб-уровень героев отряда |
| `jobs` | профессии по слотам через `\|` |

**Сила** (`squadPower`) = Σ по занятым слотам `hp × atk / 1000`, округление до целого. Грубый прокси «сколько выдержит × сколько нанесёт»: не учитывает def, spd, навыки и позиции. Годится, чтобы сравнить рост отряда и рост этапов, но не предсказывает исход боя — исход показывают `wins/losses`.

## Как читать «стены»

Стена — этап, на котором игрок застрял надолго.

- В CSV: несколько строк подряд с одним `stage_reached`, `wins = 0`, `losses = maxLossesPerSession`. Сколько строк — столько сессий ожидания.
- Сравните `squad_power` и `next_stage_power`: если сила отряда растёт медленно (только за счёт офлайн-опыта), а разрыв большой — стена будет долгой.
- Скрипт печатает сводку: когда каждый этап впервые пройден (день/сессия/часы, сколько боёв ушло) и «стену» — этап с самым долгим ожиданием в часах (от прохождения предыдущего этапа или от первой сессии). Если этап не пройден к концу симуляции — так и пишется.
- Скачок `squad_power` вместе со сменой `jobs` — смена профессии пробивает стену; сброс `avg_job_level` при этом нормален (`jobChange.resetJobLevel`).

## Что подкручивать

- **Модель игрока** — `PLAYER_MODEL` в `scripts/lib/player-model.ts` (частота сессий, терпение, роли).
- **Игру** — только данные: `data/campaign/*.json` (состав, `mult`, награды, офлайн-доход), `data/progression.json` (`campaign.enemyStatGrowthPerStage`, `exp`, `offline.capHours`, пороги смены профессии), `data/jobs/*.json` (статы и рост). Код скрипта менять не нужно.
