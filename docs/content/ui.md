# UI: токены и правила экранов

Игра рисуется на поле **1080×1920** и на телефоне масштабируется примерно ×0.36–0.4.
Значит, 26 единиц шрифта ≈ 10 px на экране, это нижняя граница читаемости. Все размеры ниже даны в игровых единицах.

Токены лежат в `src/game/theme.ts`, общие виджеты — в `src/game/ui.ts` и `src/game/screen.ts`.

## Шрифт (`FS`)

| Токен | Размер | Где |
|---|---|---|
| `FS.hero` | 56 | главная кнопка экрана («В бой», «Штурм») |
| `FS.h1` | 48 | заголовок в шапке, крупные названия |
| `FS.h2` | 40 | заголовки карточек и секций, подписи крупных кнопок |
| `FS.h3` | 36 | имена в строках списков, важные числа, кнопки в строках |
| `FS.body` | 32 | основной текст |
| `FS.small` | 28 | пояснения, статус |
| `FS.caption` | 26 | минимум: «фронт/тыл», цифры на полосах, подписи под иконками |

Шрифт **меньше 26 не используем** (это проверяет тест `tests/game-features.test.ts`).

## Цвета (`C` для текста, `TINT` для заливок)

- `C.text` (белый) — основной текст на тёмной карточке; `C.title` — заголовки; `C.muted` — пояснения; `C.dim` — служебные подписи; `C.disabled` — закрыто или получено.
- `C.gold` — золото и мощь; `C.gem` — гемы; `C.success` — готово, «в отряде»; `C.positive` / `C.danger` / `C.dangerStrong` — лучше / хуже / намного хуже; `C.error` — тост с ошибкой; `C.warning` — «ещё не готово»; `C.info` — экипировка и редкое; `C.enemy` — противник.
- На светлой карточке (`ui_panel_light`, выбранный слот) используем тёмный текст без обводки: `C.ink`, `C.inkMuted`, `C.inkSuccess`, `C.inkInfo`, `C.inkGold`.
- Обводка: `C.stroke` у светлого текста, `C.titleStroke` у золотых заголовков, `C.none` — без обводки.
- Цвета редкостей — `RARITY_COLORS` / `RARITY_TINTS` в `flow.ts`. Цвета сравнения мощи — `POWER_COLORS`.

## Отступы и размеры

- `SP` = xs 8 / s 16 / m 24 / l 40 / xl 60.
- `MARGIN` = 20 — поле экрана по бокам; `CARD_W` = 1040 — стандартная карточка во всю ширину.
- `TOUCH` = **96** — минимальная высота (и ширина) того, что нажимается. `button()` сама расширяет зону нажатия до 96, даже если кнопка нарисована ниже. Но рисовать кнопки ниже 96 всё равно не надо.

## Статы

Подписи статов на всех экранах одни и те же: **ОЗ / АТК / ЗАЩ / СКР**. Они берутся из одного места, `STAT_LABELS` в `flow.ts`.
Строку со статами собирает `statsLine(stats, sep, keys)`, бонусы предметов — `itemStatsText`, разницу статов — `diffText(statDiff(...))`.
Латинские HP/ATK в интерфейсе не пишем.

## Правила для нового экрана

1. **Каркас.** Вызываем `screen(scene, title, tab, back)`. Длинный заголовок сам обрежется многоточием.
2. **«Назад».** Кнопка в шапке всегда ведёт на логического родителя экрана:
   - герой → список героев;
   - слот инвентаря → герой;
   - этап → **его** глава кампании;
   - смена профессии → герой;
   - отряд → тот экран, откуда его открыли;
   - задания, башня и поручения → главная;
   - достижения → откуда пришли.

   Экраны из нижней навигации (Кампания, Герои, Главная) кнопки «Назад» не имеют.
3. **Нажатия.**
   - Кнопки делаем через `button()` / `dangerButton()`.
   - Карточки, слоты и плитки делаем через `pressable(scene, obj, w, h, onTap)`: при нажатии объект затемняется, а клик срабатывает, только если палец опустился на этот же объект.
   - Голый `setInteractive().on('pointerup')` не используем.
4. **Списки, которые могут не влезть**, кладём в `ScrollArea(scene, top, bottom)`:
   - объекты добавляем через `area.add(...)`;
   - обработчики кнопок и карточек оборачиваем в `area.tap(fn)`;
   - в конце вызываем `area.setContentHeight(h)`.

   Список тянется пальцем и колёсиком, справа видна полоса прокрутки. Когда палец начинает тянуть список, нажатая кнопка отпускается (событие отмены нажатия). Постраничные кнопки ‹ › для списков не делаем.
   Сейчас прокручиваются: инвентарь, герои (если их больше 5), навыки в карточке героя, подробности смены профессии, поручения, достижения, задания дня.
5. **Пустое состояние.** Если список пуст, выводим `emptyState(scene, x, y, текст)` с подсказкой, что сделать, чтобы здесь что-то появилось. Пустой экран без объяснения не оставляем.
6. **Длинные имена.** Однострочные подписи в ограниченной ширине (имена врагов и героев в слотах, предметы, поручения) обрезаем через `ellipsize(text, maxWidth)`. Перенос на вторую строку не используем: он налезает на соседние строки.
7. **Числа.** Не пишем в сцене новые размеры шрифта и цвета числами или hex-строками, берём токен. Если токена не хватает, добавляем его в `theme.ts` и описываем здесь.

## Подсказки первой сессии и авто-прохождение (R)

**Подсказки** — лёгкие, без блокирующего обучения.

- Логика — `src/game/hints.ts`: какие подсказки уже выполнены, хранится в localStorage (`chronoworld.hints`), **не** в сохранении игры. Ошибки хранилища глотаются: в худшем случае подсказка покажется ещё раз.
- Рисует `hintPointer(scene, x, y, текст, 'above' | 'below', { w, h })` из `ui.ts`: пульсирующая золотая рамка вокруг цели, прыгающая стрелка и плашка с одной строкой (`FS.body`, `C.title`). Указатель **не интерактивный** — нажатия проходят к кнопке под ним, поэтому подсказки не мешают ни игроку, ни e2e.
- На экране одна подсказка. Каждая показывается, пока игрок один раз не сделал действие:

| id | Где | Когда | Выполнена |
|---|---|---|---|
| `home_campaign` | Главная → «В кампанию» | этапов не пройдено | открыт экран кампании |
| `stage_fight` | Этап → «В бой» | первое прохождение этапа | бой начат (или пропущен) |
| `chest_claim` | Главная → «Собрать» | в сундуке есть доход | сундук собран |
| `job_change` | Главная → вкладка «Герои»; карточка героя → «Сменить профессию» | герой может сменить профессию | открыт экран смены профессии |
| `tower_open` | Главная → плитка «Башня» | башня открыта | открыт экран башни |

- Порядок на главной выбирает `pickHomeHint` (чистая функция, тест `tests/game-hints.test.ts`); подсказка пересчитывается раз в секунду вместе с сундуком.
- «Сбросить подсказки» — маленькая ссылка между «Тестовый бой» и «Сбросить» на главной. Полный сброс прогресса тоже сбрасывает подсказки.
- Значок на вкладке «Герои» в нижней навигации — сколько героев могут сменить профессию (`jobChangeReadyCount` в `flow.ts`).

**Авто: следующий этап** (как авто-бой в AFK-играх).

- Переключатель на итоге боя кампании, над нижними кнопками. Настройка, не прогресс: `autoAdvance` / `setAutoAdvance` в `state.ts`, ключ `chronoworld.autoAdvance`.
- Если он включён и бой выигран, через `AUTO_DELAY_MS` (2 с) сам начинается следующий этап: виден отсчёт «Этап N через 1.4 с» и золотая полоса. Бой идёт обычным путём (`Battle` → `actPlayStage`).
- Касание в любом месте экрана отменяет отсчёт (переключатель остаётся включённым). Выключить переключатель — тоже отмена.
- Остановки (`autoNextStage` в `flow.ts`): поражение, конец главы, следующего этапа нет, следующий этап уже пройден (повтор старого этапа не запускает цепочку повторов). Причина пишется рядом с переключателем.
