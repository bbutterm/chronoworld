# Профессии

Герой игрока = профессия + уровень профессии (в RO — «джоб-уровень») + история пройденных профессий. Профессии — JSON в `data/jobs/`, навыки профессий — `data/skills/job_<профессия>_<название>.json`. Схема — `JobSchema` в `src/core/progression/schema.ts`, правила перехода — `data/progression.json`. Все числа — заглушки, баланса нет.

## Дерево

```
Новичок (novice, tier 0, ур. профессии 1–10)
├─ Мечник   (swordman) ─┬─ Рыцарь      (knight)
│                       └─ Крестоносец (crusader)
├─ Аколит   (acolyte)  ─┬─ Жрец        (priest)
│                       └─ Монах       (monk)
├─ Маг      (mage)     ─┬─ Волшебник   (wizard)
│                       └─ Мудрец      (sage)
├─ Лучник   (archer)   ─┬─ Охотник     (hunter)
│                       └─ Бард        (bard)
├─ Вор      (thief)    ─┬─ Ассасин     (assassin)
│                       └─ Разбойник   (rogue)
└─ Торговец (merchant) ─┬─ Кузнец      (blacksmith)
                        └─ Алхимик     (alchemist)
```

tier 1 и tier 2 — ур. профессии 1–50. Переход на tier 1 — с 10-го уровня Новичка, на tier 2 — с 50-го уровня первой профессии (`progression.json → jobChange.tierLevel`); после смены уровень профессии сбрасывается в 1 (`resetJobLevel`).

## Навыки

- `skills: [{ "jobLevel": 20, "skill": "job_mage_frost_diver" }]` — навык открывается, когда герой достигает этого уровня профессии. На одном уровне — один навык.
- У каждой профессии tier 1–2 — 5–6 навыков: на уровнях 1, 10, 20, 30, 40 (у Аколита и Жреца ещё на 5), активные и пассивные вперемешку.
- Навык **без** `trigger` — активный: герой применяет готовый активный навык с наибольшим `priority` по перезарядке (`cooldown`, секунды боя), иначе — обычную атаку. **Ульты у героев нет** — энергия копится только у монстров и боссов (у них `skills.ult`).
- Поэтому пассивки героев **не дают энергию себе/союзникам** (это ничего не делает). Эффект `energy` с минусом у героя допустим только против врага (Заряженная стрела, Кража, Грабёж, Гром Юпитера — сбивают ульту монстра). Ускорение каста/перезарядки RO (SP Recovery, Магнификат, Поэма Браги) передаём через `spd` — больше ходов в бою. «На весь бой» — статус с `turns: 99`.
- Навык **с** `trigger` (`battleStart`, `turnStart`, `hit`, `kill`, `allyDeath`) — пассивка; работают все открытые.
- Если `keepSkillsOnJobChange: true`, навыки прошлых профессий (до уровня, на котором с них ушли) остаются у героя.
- Обычная атака — `basic` профессии: `basic_melee` (ближний бой), `basic_ranged` (дальний, нужен `visual.projectile`), `basic_heal` (лекари).
- Статы: `baseStats + growth × (ур. профессии − 1)`. База tier 2 ≈ статы профессии tier 1 на ур. ~30.

Правила подбора (QA T5-13…T5-17):

- Навык — **своей** профессии RO (pre-renewal): Святилище — Жрец, не Аколит; навыки перерождённых классов (Cart Termination, Acid Demonstration) у обычных вторых профессий не используем. Навык ветки-предка допустим (Рыцарь — Мечник по дереву RO: «Владение двуручным мечом»).
- Рыцарь — **мечник с двуручником** (как на спрайте: Knight со Slayer): копейных навыков (Pierce, Brandish Spear) у него нет.
- Имена: собственные имена навыков RO — калькой RU-сервера («Баш», «Магнум Брейк», «Боулинг Баш», «Маммонит», латынь Жреца с заглавных: «Кирие Элейсон», «Импозицио Манус»); описательные — переводом («Двойной выстрел», «Заряженная стрела», «Повышение ловкости»). Одно имя — один навык: у монстров и legacy-героев свои имена («Бросок», «Корневая броня», «Молитва»).
- Описание совпадает с числами: проценты статусов, число ударов, цель (`lowestHp` — «с наименьшим HP», `lowestHpPct` — «самый раненый»). Пассивки начинаются с условия («В начале боя: …», «Когда по … попали: …»).
- Отложено: id старых навыков вне правила `job_<профессия>_<навык>` (`swordman_bash`, `swordman_endure`, `novice_first_aid`) не переименованы — на них завязаны тесты и иконки.

## Термины

- **Уровень профессии** («ур. профессии»), не «джоб»/«джоб-уровень» — в данных, сюжете и документах. Экраны `src/game` пока пишут «Джоб N» — поправить там же (см. docs/qa/FIXLIST.md, P3).
- Валюта — **золото** (так во всех экранах и в `data/*`). Иконка монеты — RO Zeny, но слово «зени» в текстах не используем (вопрос владельцу — docs/QUESTIONS.md).

## Как добавить профессию

1. Скопировать похожую: `data/jobs/knight.json` → `data/jobs/<id>.json`, поменять `id`, `name`, `description`.
2. Указать `tier` и `from` — профессии, из которых можно перейти (их tier строго меньше; у tier 0 `from` пустой).
3. Роль, `baseStats`, `growth`, `basic`, `visual` (`sprite` — id из реестра спрайтов; нет спрайта — рисуется плейсхолдер, `content:check` предупредит).
4. Навыки: `npm run content:new -- skill job_<id>_<название> --from <похожий навык>`, затем добавить в `skills` с уровнем открытия ≤ `maxJobLevel`.
5. `npm run content:check`, потом `npm run check`.

## Что проверяет content:check

- `basic` и навыки существуют, `basic` без `trigger`;
- уровни открытия навыков уникальны и ≤ `maxJobLevel`;
- у tier 0 `from` пустой, у tier ≥ 1 — непустой, tier каждого источника строго меньше;
- каждая профессия достижима от Новичка по цепочке `from`.

Код проверок — `src/core/progression/validate.ts`, тесты — `tests/jobs.test.ts`.
