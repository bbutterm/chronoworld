## Работа сабагентами — волны и владение файлами

Каждый сабагент работает в своём git worktree, трогает **только свои файлы**, коммитит в своей ветке с зелёным `npm run check`; оркестратор сливает ветки по порядку и прогоняет `npm run check` после каждого слияния.

| 1 | **B. Кампания и офлайн** | T5, T6 | `src/core/campaign/**`, `data/campaign/**`, `data/units/mob_*.json`, `tests/campaign.test.ts`, `tests/offline.test.ts`, `docs/content/campaign.md` |

Общие файлы (`src/core/index.ts`, `src/core/types.ts`, схемы) меняет только оркестратор; если сабагенту нужна правка — описывает её в отчёте.

Задачи для автономной работы агента. Цель — **тонкий срез**: этапы кампании → опыт → джоб-уровни → смена профессии → навыки → сохранение, всё на данных и с тестами. Баланс, арт и Telegram — не сейчас.

## Правила для агента

1. Перед началом прочитай `docs/GDD.md` (особенно раздел 8 «Джобы»), `docs/CONTENT.md`, `README.md`.
2. Работай в ветке `claude/idle-hero-rpg-gdd-rolicg`. **Одна задача — один коммит** (`T3: …`). После каждой задачи `npm run check` должен быть зелёным, иначе не коммить.
3. Задачи идут по порядку (есть зависимости). Если задача заблокирована — пропусти, опиши причину в `docs/QUESTIONS.md`, иди дальше.
4. **Решения владельца не жди.** Если чего-то нет в GDD — выбери разумное значение по умолчанию, вынеси его в конфиг `data/*.json` и запиши вопрос в `docs/QUESTIONS.md` (формат: вопрос → что выбрано → где поменять).
5. **Никакого баланса.** Все числа — заглушки в `data/*.json`, без подгонки. Не трогай статы героев и навыки, которые уже есть.
6. **Ядро без Phaser.** Логика — в `src/core/` (чистый TS, детерминизм, время передаётся параметром — никаких `Date.now()` и `Math.random()` в ядре). Phaser только рисует.
7. **Новый тип данных = схема zod + проверка в `content:check` + раздел в `docs/CONTENT.md` + тесты.**
8. Не трогать: `assets/ro/`, `assets/ui/`, `art-research/`, `tools/`. Не добавлять Telegram, сервер, монетизацию, экипировку, фракции.
9. В конце сессии — отчёт в `docs/REPORTS/<дата>.md`: что сделано, как проверить руками, что сломано/не доделано, вопросы.

## T0. CI: проверка на каждый пуш

- `.github/workflows/check.yml`: Node 22, `npm ci`, `npm run check`, `npm run build`.
- **Готово, когда:** workflow валиден (проверь синтаксис), в README бейдж/строка про CI.

## T1. Сохранение (ядро)

- `src/core/save/`: схема `SaveState` (zod) с полем `version`, функции `newGame()`, `serialize()`, `deserialize()` (валидация + миграции по версиям), интерфейс `SaveStorage` (`load/save`).
- Адаптеры: `MemoryStorage` (тесты), `LocalStorage` (в `src/game/`, не в ядре).
- Состояние (минимум): герои (см. T3), отряд (5 слотов), прогресс кампании, ресурсы (`gold`), время последнего сбора офлайн-наград, seed-счётчик для боёв.
- **Готово, когда:** тесты: круговой serialize→deserialize, битое/старое сохранение → понятная ошибка или миграция, `newGame()` детерминирован.

## T2. Профессии (джобы) как данные

- `data/jobs/*.json` + схема `JobSchema`: `id`, `name`, `tier` (0 — Новичок, 1 — первая, 2 — вторая), `from` (из каких профессий можно перейти), `maxJobLevel`, `baseStats`, `growth` (прирост статов за джоб-уровень), `basic` (обычная атака), `skills: [{ jobLevel, skill }]` (открытие активных и пассивных навыков), `visual.sprite`.
- Конфиг `data/progression.json`: пороги смены профессии (tier 1 — джоб 10, tier 2 — джоб 50), кривая опыта (параметры формулы), флаги решений (`keepSkillsOnJobChange` и т. п.).
- Контент-заглушки (числа условные, навыки можно переиспользовать существующие или сделать простые новые):
  - tier 0: `novice`;
  - tier 1: `swordman`, `acolyte`, `mage`, `archer`, `thief`, `merchant`;
  - tier 2: `knight`, `crusader`, `priest`, `monk`, `wizard`, `sage`, `hunter`, `bard`, `assassin`, `rogue`, `blacksmith`, `alchemist`.
  - Минимум по одному навыку на каждые 10 джоб-уровней у tier 1 и tier 2 (актив или пассив, как в AFK Arena).
- Существующие `data/units/*.json` героев не удалять (на них тесты и экран подготовки), но новые герои игрока строятся из джобов.
- `content:check` проверяет: ссылки `from` существуют и tier строго меньше, навыки существуют, уровни открытия ≤ `maxJobLevel`, у каждой профессии tier ≥ 1 есть путь от Новичка.
- **Готово, когда:** контент валиден, тесты на ошибки схемы/ссылок, раздел «Профессии» в `docs/CONTENT.md`.

## T3. Герой игрока → юнит боя

- `HeroState`: `id`, `name`, `job`, `jobLevel`, `jobExp`, `jobHistory` (пройденные профессии).
- `buildUnit(hero, content, progression): UnitDef` — статы = база профессии + рост × (джоб − 1); навыки: обычная атака профессии, ульта = последний открытый активный навык, пассивки = открытые пассивные (с учётом `keepSkillsOnJobChange` и истории).
- Бой должен принимать отряд из готовых `UnitDef` (не только id из `data/units`): расширь `simulateBattle`/`createUnits` без поломки старого API.
- **Готово, когда:** тесты: статы растут с уровнем, навык открывается ровно на своём уровне, после смены профессии набор навыков соответствует конфигу, бой с героями из джобов детерминирован.

## T4. Опыт, уровни, смена профессии (ядро)

- `addJobExp(hero, amount, …)` → новые уровни, открытые навыки (список событий для UI), потолок `maxJobLevel`.
- `availableJobChanges(hero)` и `changeJob(hero, jobId)` — проверки порога и `from`; джоб-уровень сбрасывается в 1 (или как в конфиге).
- **Готово, когда:** тесты на порог 10/50, нельзя сменить в чужую ветку, опыт сверх потолка не теряет состояние, события level-up/skill-unlock корректны.

## T5. Кампания (ядро)

- Данные: `data/campaign/chapters/*.json` (или один файл) + схема: главы → этапы; этап: `id`, `name`, `enemies` (5 слотов: id монстра + множитель/уровень), `rewards` (`jobExp`, `gold`), босс-флаг.
- Монстры-заглушки в `data/units/` (`kind: monster`/`boss`): ближний, дальний, танк, быстрый, 3 босса — спрайты-плейсхолдеры (id из `docs/SPRITE_SPEC.md`: `melee`, `ranged`, `tank`, `fast`, `boss_ch1..3`).
- Рост силы врагов по кривой из `data/progression.json` (стартовая точка GDD: +8% статов за этап).
- `playStage(save, stageId, seed)` → результат боя + начисление наград (опыт — каждому герою отряда), открытие следующего этапа. Чистая функция: принимает и возвращает состояние.
- Контент: глава 1 — 10 этапов (10-й — босс). Остальные главы — не нужно.
- **Готово, когда:** тесты: нельзя играть закрытый этап, награды только за победу, следующий открывается, повтор пройденного даёт награду (или нет — по конфигу), всё детерминировано по seed.

## T6. Офлайн-награды (ядро)

- `offlineRewards(save, now)` — доход в минуту по последнему пройденному этапу (из данных этапа), лимит 12 ч (конфиг), `claimOffline(save, now)`.
- **Готово, когда:** тесты: лимит, ноль до первого этапа, повторный сбор, время назад (часы переведены) не ломает и не даёт награду.

## T7. Инструмент баланса

- `npm run balance` → CSV (`balance.csv` в корне, в `.gitignore`): день, сессия, этап, сила отряда, сила следующего этапа, джоб-уровни, профессии, золото, опыт. Модель игрока: N сессий в день, в сессии — сбор офлайна, попытки следующего этапа (реальный бой симулятором), при проигрыше — ждёт.
- Модель игрока (сессии/день, минуты между сессиями, выбор профессии) — в конфиге скрипта.
- **Готово, когда:** CSV строится за разумное время, в README описано, как читать; «стены» видны по колонке попыток.

## T8. Экраны (Phaser, плейсхолдеры)

- Новый поток: старт → Главная (сундук офлайн-наград, кнопка «Собрать») → нижняя навигация: **Кампания**, **Герои**, **Главная**.
- Кампания: список/путь этапов главы 1 (закрыт/открыт/пройден/босс) → экран отряда (5 героев игрока по слотам) → бой (текущая сцена) → итог с наградами и level-up.
- Герои: список 5 героев (профессия, джоб, полоса опыта) → карточка: статы, навыки (открытые/закрытые с уровнем), кнопка «Сменить профессию» с выбором ветки, когда доступно.
- Сохранение после каждого изменения (LocalStorage-адаптер из T1). Кнопка «Сбросить прогресс» в Главной (для тестов владельца).
- Текущий экран подготовки с 6 фиксированными героями оставить как «Тестовый бой» (кнопка на Главной).
- **Готово, когда:** можно пройти этапы 1–3, поднять героя до джоба 10, сменить профессию, увидеть новый навык в бою; перезапуск страницы сохраняет прогресс. Скриншоты экранов (Playwright, мобильный вьюпорт 432×768) — в отчёт.

## T9. Полировка боя без арта (если осталось время)

- Выход из «застревания»: ближний боец не может дойти до цели дольше N секунд → берёт ближайшего доступного.
- Лог боя для отладки на экране итога (кнопка «Лог»: текстом последние события).
- Тесты на крайние случаи: отряд из одних ближних против одних дальних, 1 против 5, все мертвы одновременно (DoT), бой с пустыми слотами.

| # | Функция | Аналог в AFK Arena | Суть |
| --- | --- | --- | --- |
| K1 | **Быстрые награды** | Fast Rewards | Мгновенно забрать N часов офлайн-дохода, лимит раз в день (дата — параметром), бесплатная попытка + платные за валюту-заглушку |
| K2 | **Сила отряда** | Team Power | Число «мощи» героя и отряда из статов/навыков; показ на экранах, в балансе |

| K4 | **Башня испытаний** | King's Tower | Отдельная прогрессия этажей, свой список, награды за этаж, каждые 5 этажей — босс |
| K5 | **Ежедневные задания** | Daily Quests | Список заданий (пройти этап, собрать сундук, сыграть в башню…), счётчики из событий, сброс по дате, награды за очки активности |
| K6 | **Экипировка (простая)** | Gear | 4 слота, 3 редкости, фиксированные статы, выпадение с этапов, надеть/снять (GDD фаза 2) |
| K7 | **Повтор и пропуск боя** | Auto-battle / Skip | Повторить этап, «пропустить» бой пройденного этапа (сразу итог) |
| K8 | **Пресеты отряда** | Formations | Сохранённые расстановки, авто-расстановка по ролям (танки вперёд) |
| K9 | **Доска поручений** | Bounty Board | Отправить героев на задания с таймером, награды по возвращении |
| K10 | **Достижения** | Achievements | Одноразовые цели с наградами |

Не делать без решения владельца: призыв/гача, звёзды/возвышение, арена/PvP, гильдии, магазин за реальные деньги, Telegram.
