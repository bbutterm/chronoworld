# Экспедиции — текстовые приключения (задача 5 плана 01.10)

## Что и зачем

Владелец: «экспедиции скучные» — отправил, подождал, забрал цифры. Идея «текстовые приключения» ему нравится.
Берём лучшее из FTL-событий, Darkest Dungeon (герой с характером решает исход), King of Dragon Pass (выбор без
«правильного» ответа, последствия — строчкой в летописи) и ивентов Slay the Spire — но коротко, для мобильного idle:
одно событие читается за 10 секунд, решается одним касанием и никогда не блокирует таймер.

1. Пока отряд в пути, с ним случается 1–3 события (1 ч — одно, 4 ч — два, 8 ч — три). Событие — 2–4 предложения в мире
   RO про эту локацию (или общее «на дороге») и 2–3 варианта выбора.
2. Игрок заходит в «Экспедиции» — у карточки кнопка «Событие». Не решил до «Забрать» — выбирается осторожный вариант
   (default), и отряд просто идёт дальше.
3. Вариант может требовать класс (линия профессии: вор, послушник, лучник…), роль (лекарь) или конкретного героя
   (Кай поджигает, Грета торгуется). Такой герой в отряде — вариант надёжный (chanceWith, обычно 95%) и показан с его
   портретом; нет — только шанс (chance). Все броски — Rng с seed из сохранения, локации, времени отправки и номера события.
4. Исходы: добыча (золото и опыт — «ступенью», предмет из добычи локации, редко гемы), запись в Летопись экспедиций,
   иногда рана (герой «ранен» — часть золота ушла на зелья у кафры, без потери героя), иногда «сблизились» (запись пары
   героев — отдельное поле экспедиций, чужую систему близости не трогаем).
5. «Забрать» показывает рассказ: событие → выбор → исход, затем добыча.

## Данные

`data/expedition_events.json` (схема `src/core/meta/expedition-events-schema.ts` → `data/schema/expedition_events.schema.json`):

- `perExpedition` — сколько событий: `[{ maxHours: 1, count: 1 }, { maxHours: 4, count: 2 }, { maxHours: 999, count: 3 }]`.
- `tiers` — ступени награды: доля «куска» базовой добычи экспедиции. Кусок = снимок золота (опыта) экспедиции / число
  событий. `none` 0, `small` 0.15, `medium` 0.3, `big` 0.5, `loss` −0.1 (рана, потеря).
- `events[]`: `id`, `title`, `locations` (пусто — общее событие для любой локации), `text`, `choices[]`:
  `id`, `label` (≤ 34 символов), `requires` (`line` / `role` / `hero`), `chance`, `chanceWith`, `default` (ровно один на
  событие, без требований, шанс 1, награда `none` — ставит «как раньше»), `success` и `fail` — исходы
  (`text`, `reward`, `item`, `gems`, `lore`, `wound`, `bond`).
- В текстах: `{hero}` — кто действовал (подходящий по требованию или случайный из отряда), `{partner}` — второй герой
  (для `bond`), `[слово|слово]` — мужской/женский род того, кто действовал.

## Сохранение (без смены версии)

- `bounties.active[].events?` — события экспедиции: `{ id, at, choice?, ok?, auto?, actor?, partner?, item? }`. Выпадают при
  отправке (детерминированно); решение сохраняется сразу — переиграть нельзя. Старые экспедиции без поля — без событий.
- `bounties.journal?` — Летопись экспедиций (последние 40 записей: время, локация, текст).
- `bounties.bonds?` — «сблизились»: `{ heroes: [a, b], location, at }` (последние 40).

## Числа и проверка

- Выбор по умолчанию даёт ровно прежнюю добычу (ступень `none`, без предметов и гемов) — старый баланс и модель игрока
  (`npm run balance`) не меняются.
- Разумный выбор (лучший ожидаемый вариант для своего отряда) — +10…20% золота и опыта. Проверяет `tests/expedition-events.test.ts`:
  все локации × сроки × случайные отряды, среднее по «лучшему выбору» в [10%; 20%], по умолчанию — 0%.
- Тесты: детерминизм, выбор по умолчанию, требование класса (с героем — chanceWith, без — chance), ссылки контента,
  старое сохранение с идущей экспедицией без событий читается и забирается.
- Экран: `npm run e2e`, скриншот окна события на ширине телефона.
