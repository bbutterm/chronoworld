# Полировка интерфейса: исследование и план (01.10)

Зачем: владелец — «игра готова, но выглядит нейро-сгенерированной, UX/UI слабые». Здесь — правила из лучших мобильных
idle/gacha RPG и Telegram Mini Apps, признаки «нейро-слопа» в игровом UI, аудит каждого экрана Chronoworld по
скриншотам и коду, токены, план из 10 итераций для параллельных агентов и идеи по производительности интерфейса.

Как снимались скриншоты аудита: `scripts/qa-save-late.ts --day 9 --from 6` (5 фиолетовых ур. ~59, мощь 14 493,
43 героя) → Playwright 390×844, `window.__game.scene.start(<сцена>)` по всем экранам; плюс `docs/qa/screens-late/*`
и `docs/qa/screens-route-late/*`. Скрипт съёмки стоит закоммитить в итерации 1 (`scripts/ui-shots.mjs`, см. ниже).

Масштаб: поле 1080×1920, телефон 390 px по ширине → **1 ед. = 0.361 CSS px** (360 px → 0.333). Все размеры ниже —
в игровых единицах; в скобках — CSS px на 390.

## 0. Главный диагноз в пяти пунктах

1. **Нет иерархии.** Семь размеров шрифта, но 30/30/32/36/40 на телефоне — это 10.8/10.8/11.6/13/14.4 px: глаз их не
   различает. Пять оттенков почти белого текста (`#ffffff`, `#eadfc6`, `#e0cfb0`, `#f0cf8a`, `#d6ae63`) — всё одного
   веса. Шрифт — системный Arial (`layout.ts FONT`): самый узнаваемый признак «собрано без дизайнера».
2. **Объясняем вместо того, чтобы показывать.** 27 строк «Нажмите…», постоянные блоки правил («Как устроен забег»),
   строки-шпаргалки под каждой кнопкой («повтор лучшего боя», «нужны копии», «Отряд собирается сам · …»), 140 вызовов
   `toast()`. Пример владельца на «Этапе»: 6 конкурирующих сигналов о силе и 3 строки инструкций над списком.
3. **Всё в одинаковой коробке.** Каждый блок — та же тёмная плитка с бронзовой рамкой (`card()` / `skin_panel`), карточки
   в карточках («Уровень и награда» внутри панели Охоты), одинаковые по весу кнопки (в Лавке 6 золотых «Купить», в
   Таверне 5 одинаковых кнопок призыва, в Башне 7 «primary» в коде).
4. **Красные точки обесценены.** «Герои 56», «61», «Город 5», «Приключения 4/8», значки на каждой плитке и карточке
   («Новый!» + красная маска + «+4» + «в отряде» на одной карточке героя). Если горит всё — не горит ничего.
5. **Telegram Mini App не доделан.** Нет `WebApp.ready()`, `expand()`, `disableVerticalSwipes()` (свайп вниз по списку или
   при перетаскивании героя сворачивает приложение!), `BackButton`, `setHeaderColor/BackgroundColor/BottomBarColor`.
   Кнопки тестера «+300 гемов / +12 ч» висят в верхней полосе у всех игроков.

## 1. Что делают лучшие (исследование)

### 1.1 Каркас экрана (AFK Arena, AFK Journey, Idle Heroes, Ragnarok M/Origin/X, Summoners War, HSR, Genshin)

- **Верх — тонкая полоса ресурсов**, только 2–3 валюты этого экрана, у каждой «+» (куда купить/добыть). Аватар+уровень
  — только на главной. Название экрана — мелко слева или вообще нет (AFK Arena: экран узнаётся по арту, не по
  заголовку). Высота полосы ресурсов ≈ 40–48 pt.
- **Низ — 4–5 вкладок** (AFK Arena: Ranhorn / Тёмный лес / Кампания / Герои / чат). Вкладка = крупная иконка + короткая
  подпись 10–11 pt, активная — подсветка/увеличение иконки, а не рамка. Высота 56–64 pt + safe area.
- **Одна главная кнопка на экран**, крупная, в нижней трети (зона большого пальца; HSR вынес меню вправо под палец).
  AFK Arena «Begin»/«Battle»: ~45 % ширины, единственный насыщенный цвет на экране.
- **Иконки вместо слов.** Награда — иконка+число, без «золото +13 815 · опыт +19 710 в запас». Статус — значок
  (галка, замок, таймер), без «закрыт», «Получено», «Готово» текстом рядом с иконкой.
- **Плотность**: на главных экранах ≤ 7±2 интерактивных зон в первом взгляде; второстепенное — за «i»/долгим нажатием.
  AFK Journey и HSR — «минималистично, без лишних украшений»; Ragnarok Origin прячет почти всё в выезжающие меню.
- **Сила**: везде одно большое число «мощь» (CP/BR) с иконкой меча. На этапе AFK показывает **мощь врага** и цвет
  сравнения (зелёный/жёлтый/красный); уровень героев и прочие требования — только когда не хватает. Ragnarok Origin/X:
  стрелка ↑ зелёная у вещи/навыка, если улучшение есть, — без текста.
- **Цвет**: фон и рамки приглушены; насыщенность — только у редкости (зелёный → синий → фиолетовый → золотой/оранжевый
  → красный, AFK: Elite/Legendary/Mythic/Ascended) и у одного акцента CTA. Красный — только «внимание»/«опасно».

### 1.3 Telegram Mini App (core.telegram.org/bots/webapps)

- `Telegram.WebApp.ready()` сразу после показа первого кадра (убирает плейсхолдер Telegram), `expand()` на старте;
  для игры — `requestFullscreen()` (Bot API 8.0+) и `lockOrientation()` в портрете.
- `disableVerticalSwipes()` — **обязательно** для игры с прокруткой и перетаскиванием: иначе вертикальный свайп
  сворачивает/закрывает мини-приложение.
- Безопасные зоны: `safeAreaInset` + `contentSafeAreaInset` (уже учтены в `viewport.ts`), события `safeAreaChanged`,
  `contentSafeAreaChanged`, `fullscreenChanged`, `viewportChanged` (уже слушаются). Закреплять UI по
  `viewportStableHeight`, не по `viewportHeight`.
- Цвета: `setHeaderColor('#0d0e0b')`, `setBackgroundColor`, `setBottomBarColor` в цвет `SKIN.bg`, иначе вокруг игры
  светлая/синяя рамка Telegram. `themeParams` для игры с собственной палитрой не нужны (не красить игру в тему чата).
- `BackButton`: показывать, когда у экрана есть `back` в `screen()`; `onClick` = тот же переход. Аппаратная «назад» на
  Android тогда работает как в игре, а не закрывает приложение. Своя «‹ Назад» в шапке может стать иконкой-шевроном.
- `MainButton/BottomButton` — для игры не нужен (рисуем свой CTA в canvas); не смешивать.
- `HapticFeedback`: `impactOccurred(light|medium|heavy|rigid|soft)`, `notificationOccurred(success|warning|error)`,
  `selectionChanged()` — уже есть таблица в `haptics.ts`. Правило: `selectionChanged` на вкладки/переключатели,
  `light` на кнопки, `medium` на CTA «В бой», `success` на победу/получение, `heavy` — фиолетовая+ карта.
- `enableClosingConfirmation()` — только пока идёт бой/призыв (не держать всегда).

## 2. «Нейро-слоп» и любительский UI: признаки и лекарство

| Признак | Как выглядит у нас | Лекарство |
|---|---|---|
| Системный шрифт | Arial везде (`FONT`) | 2 гарнитуры: заголовки с характером (кириллица), текст — гуманистический гротеск; цифры — табличные |
| Шкала шрифтов без шага | 30/30/32/36/40/48/56 (шаг 1.07–1.11) | 5 размеров с шагом ~1.25, 2 начертания |
| Одинаковая коробка у всего | `card()` с бронзовой рамкой вокруг каждого блока; коробки в коробках | 3 уровня поверхности; рамка только у «поднятых» карточек; секции разделять отступом и заголовком, а не рамкой |
| Всё по центру | центрированные заголовки, абзацы, подписи в карточках | выравнивание по левому краю для текста и списков; по центру — только заголовок модалки и CTA |
| Пояснение к каждому элементу | «Нажмите на героя или перетащите его на место», «повтор лучшего боя», «нужны копии», «Отряд забега — нажмите, чтобы изменить» | интерфейс сам себя объясняет: слот пульсирует, курсор-рука один раз; правила — в «i» |
| Текст вместо иконки | «закрыт» под замком, «✓ Получено», «Готово», «золото +… · опыт +… в запас» | иконка+число; статус — значок |
| Эмодзи/символы как иконки | «⚔», «✓», «›», «‹», «×», «↕», «★» в подписях кнопок | контурные иконки скина (`skinIcon`) одного веса |
| Повторяющиеся тосты | тост на каждое действие, «×N» | тост только для ошибки/результата, которого не видно на экране; успех — анимация в месте действия |
| Одинаковый вес кнопок | 6 золотых «Купить», 5 кнопок призыва, «Улучшения»/«Начать забег» почти равны | 1 primary; вторичные — тёмные; третичные — текст-ссылка/иконка |
| Приглушённый серый текст | `C.dim`, `C.placeholder`, `C.disabled` мелким кеглем поверх тёмного фона | вторичный текст ≥ 4.5:1 и ≥ 36 ед.; «третичный» не использовать для смысла |
| Общие слова | «Новое!», «Отлично», «Готово», «Сил хватает», «Наградa за вехи пути» | конкретика: глагол + объект («Забрать 3»), числа вместо прилагательных |
| Одинаковые карточки-плитки 2×2 с иконкой, заголовком и 2 строками | Город, Приключения | разный размер по важности, арт вместо круглой иконки, одна строка статуса |
| Нет «сока» в ключевые моменты | победа = табличка с цифрами; итог главы = пустая плашка «Отряд готов к новым землям» | 3–4 «момента» отполировать до блеска (победа, призыв, вознесение, новая глава) |
| Подсказки-плашки, закрывающие контент | плашка «Слушаете свою музыку?…» поверх шапки Города, NPC-реплика поверх панели Охоты | одна подсказка за сессию экрана, не поверх данных; лучше — «тренер-строка» в пустом месте |
| Счётчики-«простыни» | «Получено 16 / 16», «Писем: 5», «Предметов: 183 · свободно: 22», «Героев · 43», «Призывов: 105» | показывать только если число влияет на решение |
| Дублирование | «Этап 6-1» в шапке + «Отмель у Излуда» + «Награда: …» + «Шанс: …» | заголовок = название места; номер — бейдж |

### 2.4 Дисциплина красных точек (правило для `navBadges.ts`, `flow.ts`, `heroCard.ts`)

1. Красная **точка без числа** — «можно сделать что-то выгодное сейчас» (забрать сундук, бесплатный призыв, вознести).
2. **Число** — только для счётных входящих: письма, награды заданий/достижений к получению. Максимум «9+».
3. На вкладке навигации — точка, если внутри есть хотя бы одна точка; число не суммировать (сейчас «Герои 56»).
4. «Новый!» — показывать один раз (до первого открытия карточки), не красным, а золотой искрой; не вместе с точкой.
5. На карточке героя — не больше **одного** угла-значка: приоритет «вознести» > «вещь лучше» > «новая история».
6. Не значок: «Башня — этаж по силам», «можно отправить экспедицию», «осталась попытка охоты» — это постоянное
   состояние, а не событие (сейчас даёт вечные 1/3/4 на «Приключениях»).

## 3. Принципы Chronoworld (измеримые)

1. **Одна главная кнопка.** На экране ровно одна `primary` (золото); ≤ 2 вторичных; остальное — иконки/ссылки.
   Проверка: в построенной сцене ≤ 1 видимой кнопки с текстурой `skin_btn_gold` (тест по `children`).
2. **Пять размеров шрифта, два начертания.** Только токены `T.display/title/heading/body/caption` (см. §4); bold —
   только заголовки и числа. Никаких `fontSize` литералов в сценах (линт).
3. **Ноль инструкций в постоянном UI.** Строки «Нажмите…», «…, чтобы…» запрещены в сценах; объяснение — анимацией
   (пульс цели один раз), иконкой «i» или в первой подсказке. Линт: `grep -c "Нажмите" src/game/scenes == 0`.
4. **Иконка + число вместо фразы.** Награды, цены, статусы — `rewardRow()`/`chip()`; текстом — только названия и
   сюжет. Строка интерфейса ≤ 40 символов, описание ≤ 2 строк.
5. **Три поверхности, одна рамка.** Фон-сцена → поверхность (без рамки, заливка 70–85 %) → поднятая карточка
   (рамка 2–3 ед. бронза). Карточки в карточках запрещены; секции отделяются отступом `S.xl` и заголовком.
6. **Левое выравнивание.** Текст, списки, подписи статов — по левому краю, сетка 12 колонок по 72 ед. с полями 48;
   центр — только заголовок модалки, CTA и «момент» (победа, призыв).
7. **Цвет по ролям.** Акцент-золото только у CTA и «можно забрать»; редкость — только у рамок героев/предметов;
   красный — опасность/нехватка; зелёный — лучше/готово. Литералов `'#…'`/`0x…` в сценах нет (сейчас 83 + 249).
8. **Красная точка — бюджет.** ≤ 3 точек на экране в обычной сессии; число только у писем и наград; вкладка — точка.
9. **Отклик < 100 мс, анимации из 6 длительностей.** Нажатие 80/120 мс; панели 220/140; награды — сценарий из §4.6.
   Вместо ~40 разных `duration` — токены `M.*`.
10. **Моменты — дорого, рутина — тихо.** Победа, призыв фиолетовой+, вознесение, новая глава, первый вход в режим —
    полноэкранная хореография со звуком и вибрацией; рутина (покупка, надеть вещь) — локальная анимация без тоста.
11. **Требования показываются только при нехватке.** «Сил хватает», «уровень ок», «бесплатно» — не писать; писать
    «Не хватает 2 600 мощи» красным, когда это правда.
12. **Telegram-родной.** `ready/expand/disableVerticalSwipes`, `BackButton` = «Назад» экрана, цвета шапки/низа = фон
    игры; никаких тестовых кнопок вне режима тестера (`?tester=1` или флаг в сохранении).

## 4. Дизайн-токены (предложение для `src/game/theme.ts`)

Поле 1080 ед.; 390 px → ×0.361; 360 px → ×0.333. Проверять по 360 px (худший случай).

### 4.1 Шрифт

Гарнитуры (с кириллицей, самостоятельный хостинг woff2, подмножество кириллица+латиница+цифры ≈ 25–40 КБ каждая;
загрузка через `document.fonts.load()` до первой сцены — иначе Phaser.Text запечёт Arial):
- заголовки — **Philosopher Bold** или **Alegreya SC** (фэнтези-антиква, читается в 18+ px);
- текст и цифры — **Rubik** / **Golos Text** / **Onest** (Medium 500 и Bold 700), `font-variant-numeric: tabular-nums`
  для счётчиков (у Rubik цифры ровные).
Решение — владельцу (один шрифт для заголовков; пробные скриншоты 2–3 вариантов в итерации 1).

| Токен | ед. | px@390 | px@360 | Начертание | Где |
|---|---|---|---|---|---|
| `T.display` | 88 | 31.8 | 29.3 | заголовочная, bold | «ПОБЕДА», «Глава 5», имя героя на карточке, мощь крупно |
| `T.title` | 60 | 21.7 | 20.0 | заголовочная, bold | заголовок экрана/модалки, CTA «В бой» |
| `T.heading` | 48 | 17.3 | 16.0 | текстовая, bold | заголовок карточки/секции, кнопки, важные числа |
| `T.body` | 40 | 14.4 | 13.3 | текстовая, medium | основной текст, строки списков, описания навыков |
| `T.caption` | 34 | 12.3 | 11.3 | текстовая, medium | подписи под иконками, бейджи, вкладки, статы |

Межстрочный: body 1.35, caption 1.25, заголовки 1.15 (`lineSpacing` в Phaser = (k−1)·size). Обводку (`stroke`) на тексте
по тёмной поверхности **убрать** (сейчас `OUTLINE` 4 ед. почти везде — делает текст «жирным и грязным»); оставлять
только на тексте поверх арта (бой, карта, диорама) — тень 0/3 ед. 50 % вместо обводки.
Тест `tests/game-features.test.ts` («шрифт не меньше 30») поднять до ≥ 34.

### 4.2 Отступы (сетка 8)

`S = { xxs: 8, xs: 16, s: 24, m: 32, l: 48, xl: 64, xxl: 96 }` — поля экрана `S.l` = 48 (сейчас `MARGIN` 20 ≈ 7 px —
контент прилипает к краю), внутренний отступ карточки `S.m` 32, между карточками `S.s` 24, между секциями `S.xl` 64,
между строкой подписи и значением `S.xxs`. Ширина контента: 1080 − 2·48 = 984.

### 4.3 Радиусы

### 4.6 Движение

`M = { press: 80, release: 120, fast: 140, base: 220, slow: 360, emphasis: 600, count: 900 }`,
`E = { out: 'Cubic.easeOut', in: 'Quad.easeIn', inOut: 'Sine.easeInOut', pop: 'Back.easeOut' }` (сейчас 8 разных
easing и ~40 длительностей: 90, 110, 120, 140, 160, 180, 200, 220, 250, 260, 300…).

- Нажатие: scale 1 → 0.96 за `M.press` `E.out`, отпускание 0.96 → 1 за `M.release` `E.pop`; подпись не «проседает»
  отдельно (сейчас и scale 0.97, и сдвиг подписи на 6 — двойной эффект).
- Модалка: шейд 0 → 0.65 за `M.base`; окно scale 0.92 → 1 + alpha за `M.base` `E.pop`; закрытие `M.fast` `E.in`.
- Лист снизу (новый компонент для «i», фильтров, подробностей): y + 120 → 0 за `M.base` `E.out`.
- Список: stagger 24 мс/строка, максимум 250 мс (уже так в `staggerIn`).
- Тост: вход `M.fast`, показ 2000 (ошибка 3000), выход `M.base`.
- Награда (сундук, итог, письмо): иконки вылетают из точки (`M.slow` `E.out`, разброс 40 мс), число — `countUp`
  `M.count`, «таблетка» валюты — bump 1.15 за `M.fast`.
- Раскрытие призыва: рубашка дрожит 300 → вспышка 150 → разворот 250; синяя — +лучи; фиолетовая+ — пауза 400,
  затемнение фона, `heavy` вибрация, звук «редкое». Пропуск по тапу всегда.
- Победа: затемнение поля 200 → «ПОБЕДА» scale 1.4 → 1 `E.pop` 360 → звёзды/лучи → награды по одной (по 120 мс) →
  кнопки появляются последними (через 600 мс), чтобы не нажать случайно.
- «Уменьшить анимацию» — всё сразу в конечное состояние (уже есть `juiceOn()`).

## 7. Производительность интерфейса

### 7.1 Что видно уже сейчас (Playwright, 390×844, сохранение поздней игры, после постройки сцены)

| Сцена | Объектов | из них `Text` | Контейнеров | Твинов |
|---|---|---|---|---|
| Stage | 499 | **221** | 65 | 2 |
| Squad | 466 | **211** | 62 | 0 |
| Heroes | 450 | 86 | 114 | 24 |
| Expeditions | 249 | 78 | 23 | 5 |
| Inventory | 248 | 73 | 33 | 2 |
| Achievements | 244 | 93 | 28 | 2 |
| Campaign | 239 | 61 | 23 | 14 |
| Chronicle | 219 | 85 | 40 | 6 |
| Hero | 217 | 79 | 25 | 3 |
| Home | 167 | 34 | 26 | 8 |

Каждый `Phaser.Text` — свой canvas + своя текстура в GPU: при создании — `measureText` и загрузка текстуры, при
отрисовке — разрыв батча (новая текстура = новый draw call). 221 `Text` на Этапе ≈ 220+ draw calls и сотни мс
постройки на слабом Android. Холсты скина (`skin_*`, иконки, рамки карточек) — тоже отдельные текстуры.

### 7.2 Что делать

1. **Меньше текста — меньше `Text`.** Чистка текстов (итерации 4–9) сама по себе уберёт 30–50 % `Text`. Цель: ≤ 80
   `Text` на любом экране меню.
2. **BitmapText для чисел и коротких подписей.** Растровые шрифты уже генерируются для цифр боя (`numberFont.ts`) —
   расширить на цифры уровня/мощи/цен (набор `0-9 .,+−/×%` и `ур.`), один атлас → один батч на все цифры экрана.
3. **Один атлас для скина.** Склеить `skin_*` холсты и контурные иконки в одну canvas-текстуру при загрузке (как
   `packedTexture.ts`) — поверхности, кнопки, иконки, значки рисуются одним батчем.
4. **Виртуализация списков.** `ScrollArea` строит все строки сразу (43 героя × ~10 объектов). Строить видимые ± 1
   экран, переиспользовать строки при прокрутке (пул), остальное — лениво.
5. **Кэш карточек героев.** `drawHeroCard` — 10–15 объектов на карточку; статичную часть (рамка, фон, имя, ромбы)
   рендерить в `RenderTexture`/`snapshot` по ключу `(heroId, rarity, level)` и показывать одним `Image`.
6. **Твины.** Heroes держит 24 твина (сияние «Новый!», пульсы) — для элементов вне маски `ScrollArea` ставить на паузу;
   пульсы — один общий твин на значение, к которому привязаны все значки (`heartbeat` уже один на сцену? проверить).
7. **Шрифты.** Предзагрузка woff2 до `Boot` (иначе перерисовка всех `Text` после загрузки шрифта); подмножество глифов.
8. **Перерисовки.** Таймеры «Полон через 10:19», сундук, «через 2 ч 44 мин» — `setText` раз в секунду, только если
   строка изменилась (проверить `HomeScene`/`CampaignScene`/`ShopScene`).
9. **Частицы фона** (светлячки на всех экранах, `ambient.ts`) — только на главной/карте; на слабых — выключать
   (`perf.ts` уже определяет слабое устройство).

### 7.3 Как мерить

- `npm run perf` — бой (CPU ×4): «шаг Phaser», JS за бой, объекты/`Text`, утечки. Цель после итерации 5 — не хуже
  текущих 9.5/18.0 мс шага при новых эффектах.
- `npm run perf:load` — холодный старт прод-сборки (CPU ×4, Fast 3G): время до заставки, экрана загрузки, главной.
  После добавления шрифтов — проверить, что время до главной не выросло > 150 мс (шрифты ~60–80 КБ).
- **Новый `npm run perf:ui`** (итерация 10, `scripts/perf-ui.mjs`, порт `PERF_UI_PORT` 5195): по сохранению
  `qa-save-late` для каждой сцены из списка — `scene.start`, время от вызова до конца `create()` и до первого кадра
  (`performance.mark` в `transitions.ts`/обёртке `create`), число объектов/`Text`/контейнеров/твинов (обход
  `children` — как в аудите), **draw calls за кадр** (в `addInitScript` обернуть
  `WebGLRenderingContext.prototype.drawElements/drawArrays` счётчиком и снять за 1 кадр), холодный и повторный
  вход; CPU ×4. Порог падения: create > 120 мс (CPU ×4) или > 120 `Text` на сцене меню. `PERF_UI_JSON=файл` — сырые
  цифры в отчёт до/после.
- Оговорка (как в `docs/content/performance.md`): в headless Chromium WebGL программный — смотреть время JS и
  счётчики, а не интервал кадров.
